# Parametric EQ

**Sources:** `patch/peq.h`, `patch/peq.c` (shared), `patch/peq_player.c` (hciplayer), `patch/peq_ui.c` (the page), `patch/peqpage.c` (the preset page), `patch/peqlib.c`, `patch/peqlib.h` (the Presets page), `patch/autoeq.c` (the AutoEq download page), `patch/pcnet.c` "AutoEq" (its network job),
`tools/mod_player.py` (the hciplayer step), `tools/pod_ui.py` `build_peq_page` / `build_peqpage_page`, `tools/peq_graph.py` (the preset page's model), test `test/pod/peq.py`, previews `tools/preview_peq.py`, `tools/preview_peqpage.py`.
User instructions: [guide](../guide.md#equalizer). Based on Diamond Bond's open-source parametric EQ for the Q2 (MIT): the preset layout, the APO parser, the RBJ designs, Auto preamp, the ramped engine, the DSD pass-through and
the reload on stock's gain command are its; the carried filter memory is its idea, built on this player's own trigger. 3EQ, crossfade and the visualizer tap are not part of this feature.

## What it does

**Settings → Playback → EQ** (its value: Off, the preset that plays, or the 10-Band EQ's curve name) opens the Equalizer page: stock's Equalizer switch, **10-Band EQ** (our ten-band curve, below; its curve's name in grey before the check) and every APO / AutoEQ `.txt` file in `/mnt/mmc/EQ` (sorted by name, shown without `.txt`, at most `PQ_ROWS` = 64). Its last card holds two link rows: **Edit 10-Band EQ** (the curve name; the editor) and **Presets** (the number of files; the Presets page, download and management, below).
The row that plays has a check (below). A tap on a preset's name parses it,
saves the state record, turns stock's Equalizer on if it was off, and the new curve plays within a block (a 20 ms ramp). A file the
parser refuses shows "Cannot read this preset" and changes nothing. With no files (or the card out) a hint says where they go.

The equalizer runs in **hciplayer**, at every sample rate (stock's skipped anything above 48 kHz), on every output (the headphone
DAC, USB, Bluetooth: it sits before ALSA). DSD (the vendor's `dsdiff` driver, FFmpeg's `ffdsd*`) passes untouched. With stock's
switch off the player deletes the filter, so playback is stock's, bit for bit. Stock's slider page, the only place that showed the note
"EQ only for files below 48kHz." (`eq_only48kmsg`, `label_only48msg`), is retired (below), so the text is stock's and unseen. Our own grey note "EQ is not applied to DSD." (`DSD_NOTE`) ends the Equalizer page and the 10-Band editor.

## The player (`patch/peq_player.c`, `tools/mod_player.py`)

hciplayer (`a6450374…`, MPlayer 1.3.0 modified) is a slightly different build of the player the Q2 EQ patches: `$gp` `0xb16750` and
`mpctx` `0xaf9e30` match, code addresses do not. `tools/mod_player.py` pins the binary, its words and the facts the C reads, then:

| Edit | Address | Stock | Patched |
|---|---|---|---|
| equalizer `af_info` open slot (`af_info` at `0x893808`: info, `"equalizer"`, author, comment, flags 1, open) | `0x89381c` | `0x44fd14` (`af_equalizer` open) | `peq_open` |
| `mcl-seteq`'s rate gate: `beqz` to `===setequalizer off===` | `0x42ce34` | `0x10400098` | `nop` |
| the playback loop's insert gate: `bnez` around the add `0x42fbc4` | `0x42fa78` | `0x14400052` | `b 0x42fbc4` |
| spare `PT_NULL` (PH[10]) | | | `PT_LOAD` RWX at `0xe10000` (last stock LOAD ends `0xe03b38`) |

The payload is `peq.c` + `peq_player.c` built with `PEQ_PLAYER`, `-mnan=2008 -fno-math-errno` (hciplayer is FP64, NaN2008), linked
at `0xe10000` with no `.bss` (6.6 KB; per-instance state is heap). libc goes through hciplayer's own PLT slots (`.rel.plt`
`R_MIPS_JUMP_SLOT`; the stub sets `$gp` and `$t8` = the slot, which PLT0 expects): `memset memcpy memcmp strcmp strlen calloc free
fopen64 fread fclose clock_gettime __pow_finite cos sin`. No new import.

**How stock drives it.** demo's `set_equalizer_value(mode)` (`0x4d851c`) sends `{mcl-seteq\g0|..|g9|flag}`: the mode's ten gains
(dB) and flag 0 while `equalizer_flag` is 0, else 1 (2 while playing). hciplayer parses the gains into `0xb10df4`; flag 0 deletes the
filter (`0x42929c`), 1 or 2 set the insert state (`0xb10df0`) to 2, and the playback loop's `0x4291cc` finds or `af_add`s
`"equalizer"` and sends `AF_CONTROL_EQUALIZER_GAIN | SET` (`0x40001d00`) for channels 0..7 with those gains. The player re-adds
the filter at each file. So the filter:

- `peq_open`: control / uninit / play, `mul` 1, `data` and `setup` calloc'd; `/mnt/mmc/m1plus-off` present → this instance passes
  everything through (the kill switch).
- `REINIT` (`0x10000100`): a DSD codec, a rate outside 8–384 kHz or a special format → accepted as it comes, played untouched.
  Otherwise the curve (below) compiled for this rate and channel count, and the chain asked for float (`0x1d`, 4 bytes).
- `GAIN SET` channel 0: the curve read again (from the record, or the gains it carries); a different one goes through the engine's
  20 ms crossfade. Other channels, `GAIN GET` (ten zeros) and the command line (`0x20000300`) change nothing.
- `play`: the cascade on float blocks of the negotiated format, in place; steady bypass leaves the block bit-exact.

**Carried filter memory (a gapless join).** Static RE of hciplayer (stock `a6450374…`): the filter chain is rebuilt for every file, on
the one playback thread. `uninit_player` (`0x42def4`; called from the file loop at `0x4217d8`) runs `uninit_acodec` (`0x42e0a0`)
first: `uninit_audio` `0x47e600` -> `af_uninit` `0x44c630` -> each instance's `uninit`, then the demuxer is freed. The next file
(gapless: the swap at `0x422244`, the preloaded demuxer and decoder; or a normal open) then runs `reinit_audio_chain` `0x42e680`
(`init_audio_filters` `0x47ef04`, its only caller), and the playback loop's insert `0x42fbc4` -> `0x4291cc` `af_add`s `"equalizer"`:
`peq_open`, `REINIT`, `GAIN SET`, first block. So the old instance is gone before the new one opens, never two at once. The preload
thread (`0x42b834`; the `set-gapless` / `set-nexturl` commands) only opens the stream, demuxer and decoder; it never touches the
filter chain. The same rebuild (`af_uninit` + `0x42e680`) follows a chain change on the same file (`0x42fa3c` / `0x42faec`: output
change, speed...) and stop/skip are the same `uninit_player`: nothing in the chain tells a natural end from a skip, so the player asks
the demuxer: `mpctx->d_audio` (`+0x34`) `->eof` (`+0x1c`), the one the audio EOF test at `0x42f790` reads (pinned).

In `patch/peq_player.c`: an instance that filtered a block and is going away (`uninit`) copies `dsp.current.z` into `carry` (payload
`.data`, 4.9 KB, one writer) with the preset, rate, channel count and `CLOCK_MONOTONIC` ms, only when the demuxer is at its end
(`eof`), the curve is settled (no ramp or pending update, not bypass), the state is finite and the kill switch was off; otherwise it
clears `carry`. The next instance's first block adopts it once (taken or not, `carry` is then empty) when the rate, channel count
and the whole preset (memcmp: bands, preamp, balance, Auto) match and the join is under 3 s old. Everything else starts from zero
memory as before: a skip or stop (eof 0), a pause or the album's end (older), a rate or channel change, a different preset, DSD,
an out-of-range rate or the kill switch (these also clear `carry`), a bypass preset. An instance that never played (a chain rebuilt
before the first block, a second `REINIT`) neither takes nor clears it. A preset change after the join goes through the 20 ms
crossfade from the adopted memory as always; one that lands between the open and the first block is a different preset at the join
(zero memory). Sample format is always float after `REINIT`, so it is not part of the key. Seek, pause and resume send nothing to
the filter and are unchanged (the memory runs on across a seek); a `REINIT` on a playing instance still resets it. No thread, timer
or new hook: `clock_gettime` is hciplayer's own PLT import (the only addition to the libc list).

**The curve.** The state record `/mnt/data/m1plus/playback-eq` (`M1PEQ02\0` + `peq_state`, 1160 bytes: mode, the preset, the file name, then the 10-Band EQ's `curve`, `preamp`, `gain[10]`, `custom[10]`): `PEQ_FILE` plays its preset;
`PEQ_TENBAND_MODE` (0), a missing record or any invalid one (magic, size, mode, a band out of range, an unterminated name, a curve outside 0..9, a preamp outside -1..12, a gain outside ±12 dB or not finite) plays the record's ten `gain[]` (a missing or invalid record: Flat, preamp Auto) as ten RBJ peaking bands at 31 Hz–16 kHz, Q 1.41, plus the preamp (`PEQ_PREAMP_AUTO` -1: the engine's Auto, below; 0..12: that many dB down). An older record version is not read (it starts as Flat; stock's curve is not carried over). Stock's own `af_equalizer` (parallel
band-passes) is not used; its curve is close, not identical. Stock's ten gains in `mcl-seteq` (`0xb10df4`) are not read: stock's slider page is retired and changes nothing audible. Control runs on the playback loop, never in the PCM callback.

**The engine** (from the Q2 EQ): up to 30 bands, each both channels or one side; RBJ peak and Q-form shelves in double; preamp after the
cascade; balance turns one side down; Auto preamp (`automatic` 1: a file without `Preamp:`) is minus the largest |H|² of either side
over DC, Nyquist, 1024 log points and the band centres at the rate playing, never a boost, at most 60 dB. A band at or past Nyquist is
skipped at that rate. Denormals are flushed (`+ 1e-18 - 1e-18`); non-finite input becomes 0; samples above ±1 are kept for stock's
volume, the output converter clips.

## The parser and the record (`patch/peq.c`)

APO / AutoEQ text, at most 16384 bytes, lines of 512: `Preamp: <dB> dB`, `Channel: L|R|all` (scoping the filters after it; a side's
preamp becomes the common preamp plus `balance`), `Filter [n]: ON|OFF PK|PEQ|LS|LSC|HS|HSC Fc <Hz> Hz Gain <dB> dB [Q <q>]`,
`# comments`, a BOM, CRLF, a decimal comma. OFF filters and blank `Fc 0` slots are skipped; LS/HS without Q are slope 0.9, LS/HS
with Q move the corner to the centre (Equalizer APO's rules). Ranges 20–20000 Hz, ±24 dB, Q 0.1–10, preamp −60..24 dB, 30 bands.
**Lenient:** what the engine has no band for is skipped and counted (`peq_error.skipped`, 0 on a clean file), not refused: a command other than `Preamp` / `Channel` / `Filter` (`Device:`, `Include:`, `Copy:`, `GraphicEQ:` ...), an ON filter of another type (`LP HP BP NO AP LSQ HSQ` ...: any type word that is not PK / PEQ / LS / LSC / HS / HSC; an OFF one is not counted, it was never there), and a `Channel:` set that names a channel other than L, R, all (C, LFE, SL ...): its preamp and the ON filters after it are skipped until the next `Channel:`, never applied to the wrong side. Still refused (line and reason, `peq_error`): a malformed number or form on a line that is ours (a `Preamp`, `Channel` or a filter of a supported type), a value out of range on an ON filter, more than 30 bands, an oversized file or line, and a file with **no ON band the engine has** ("no usable filter", line 0; an empty file, a file of only skipped lines or only OFF filters). The count is not shown anywhere (a successful tap changes nothing visible; the AutoEq downloads have none). The parser is demo's only: hciplayer reads the parsed record, so the player and its safety rules are unchanged.
The record is written whole by demo (`.tmp`, `fsync`,
`rename`) and read by both binaries with `fopen`/`fread`.

## The page (`patch/peq_ui.c`)

`ui/m1plus_peq.bin` (`kind='peq'`) is a [Settings cards](settings.md) page: the same builder (`build_cards_page`, `PEQ_PAGE.layout`),
the same numbers (`tools/pod_settings.py`), neutral white and grey. Card 1 is the Equalizer switch row alone (`pod_row0`,
`pod_switch0`), with the grey output line under it (`pod_note0`, one line: "For Headphones", "For Line Out" or "For USB DAC", set by `peq_ui.c` from `peqout_current`, see "Per-output EQ"). Card 2 is the picker: `pod_row1` 10-Band EQ (a grey curve name `pod_value1` before its check, always shown: `Flat`, `Rock`, `Custom` ..., `peq_curve_key`), then `PQ_ROWS` preset rows (`pod_label<i>` empty in the asset, hidden and
insensitive), a check `pod_check<i>` on every row of it (shown on the one that plays). With no preset,
10-Band EQ is the card alone (a single piece) and the hint ("Download headphone presets in Presets, or copy APO .txt files into EQ on the card.") is a note under it: `pod_note1`, hidden in the asset, a wrapping `label` (`pod_note1_t`, three lines,
`Note(lines=3)`; the payload turns its line wrap on). Card 3 is the bottom card of two link rows: `pod_row66` Edit 10-Band EQ (`ACT_PEQ_TENBAND`: the grey curve name in `pod_value66`, a chevron, no glyph; its tap opens the 10-Band editor: `pq_on_tenband` calls `tenband_open`, `patch/tenband.c`) and `pod_row67` Presets (`ACT_PEQ_PRESETS`: a grey count of every `.txt` on the card in `pod_value67`, a chevron, no glyph); `peq_ui.c` opens the Presets page (`peqlib_open`). The page ends with `pod_note2`, the DSD note (one line, always shown, after the bottom card; `peq_items` ends with it). A preset row has no chevron and no zone: a tap anywhere on it selects it. The page is not exported as rows: `patch/m1plus.c` `open_page` binds nothing
generic for it and calls `peq_opened(win)`, so nothing is bound twice; a page without the rows binds nothing.

The preset rows come and go at run time, and a card is drawn by its rows' background pieces, so `pq_layout` also sets each shown
row's piece: with n presets 10-Band EQ is `pod_cd_top` and the last row `pod_cd_bot`, the rows between `pod_cd_mid`, and with none
`pod_cd_single` (`pod_settings.peq_pieces(n)`, the model the tests check against). The change is
`widget_set_prop_str(row, "style:<state>:bg_image", piece)` (already pinned, `0x66f8a8`; AWTK turns it into the widget's mutable
style, as the Show page's sheet card does) for normal, over, focused and disable, and the `_down` twin for pressed; only when the
piece changes. The hairline (`pod_hair`, looked up inside its row) is shown on every row of the card but the last. Rows are shown and
hidden with `widget_set_visible` + `widget_set_sensitive`, which relayouts the list: the stock layouter stacks the visible rows in
child order, so nothing is moved or restacked; `virtual_h` is also set from the model (`POD_PEQ_BASE`, `POD_PEQ_HINT_H`, `POD_ROW_H`)
only so that a list that got shorter is not left scrolled past its end. The switch row is stock's switch handler (`on_eqswitch_onclick` `0x49d750`) as is: flip `equalizer_flag`
(`0xa05ac2`), `write_int_config(flag, "PLAYSET", "EQFLAG")`, `set_equalizer_value(equalizer_mode)` (`0x97cb00`, 1..11, clamped by
`config_init`). A preset or 10-Band EQ (a tap only picks: mode 0, the record's curve, gains and preamp kept; a file keeps them too): save the record (a failed save says "Not saved" and keeps the old record and mark), then
turn the switch on as above, or with it on call `set_equalizer_value` again; either makes the player send the gain command the
filter rereads on. Back in front (after stock's Equalizer page) the folder and the switch are read again. No hook, no timer. The Settings EQ row is
`ACT_PEQ` (a value row opening the page, `patch/m1plus.c`); its value (`VK_EQ`) is Off while the switch is off, else the preset's name
(`peq_playing_name`, read from the record) or, for the 10-Band EQ, its curve name as a translation key (Flat when there is no record); stock's preset name is no longer shown. It follows each time
Settings is back in front.

## AutoEq download (`patch/autoeq.c`, `patch/pcnet.c` "AutoEq", `patch/peq_ui.c` `peq_select`)

**Data** ([AutoEq](https://github.com/jaakkopasanen/AutoEq), MIT, Jaakko Pasanen): `results/INDEX.md` on `master` through `https://raw.githubusercontent.com/jaakkopasanen/AutoEq/master/results/` (0.85 MB, 8,850 lines in 2026-11: `- [Name](./Source/Kind/Name) by Source[ on Target]`, `Kind` the directory under the source, which may start with a target: `over-ear`, `GRAS 43AG-7 over-ear`, `in-ear`, `earbud`), and a result's file at `<base><path>/<Name> ParametricEQ.txt` (about 500 bytes; the path is the index's own, percent-encoded). 22 sources; oratory1990 has 736 lines, Rtings 795, crinacle 2,036. There is **no source filter**: results show every source, and the source is in each row's grey line (Rtings has two targets, B&K 5128 and HMS II.3, which the line tells apart).

**Entry.** The Presets page's first row, **Download from AutoEq** (`ACT_PEQ_AUTOEQ`, the Lucide `download` glyph, a chevron; `pod_row0`), opens the page with `autoeq_open`. The Equalizer page has no download card and no note.

**The page** is its own window, `m1plus_autoeq` (`tools/pod_ui.py` `build_autoeq_page`, `tools/pod_pages.py` `AUTOEQ_PAGE`), built as Radio's search level is (`m1plus_radio`): the glass navbar with Back (`btn_return`) on the left, the title "AutoEq" (the existing string, the same in every language: "Download from AutoEq" is too wide in Japanese) and Now Playing's disc on the right; the field under the bar at y 56, the page's width (296, `RD_FIELD_W`, no round X: Back does what X did, closes the page and stops the job), its text 224 (`AE_TEXT_W`); one list holding one painted content view, our keyboard embedded by `keyboard_attach`. The list is at `AE_LIST_Y` 98 (the bar's 50 plus Radio's search list top 48, `RP_TOP_SEARCH`), `AE_LIST_H` 352 to the window's bottom, the list and its scroll view resized. The Search page's chip row and line are not in this asset. `search.c` is not involved (two pages never coexist: one keyboard at a time). Rows are `AE_ROW_H` 52 px (Search's `SE_ROW_H` 60 less 8; no existing two-line row is shorter: Songs / Podcasts / Search are 60-64) with no thumbnail: the name (21 px, box `LIST_TITLE_H` at y `AE_TITLE_Y` 3), the grey line (18 px, box `LIST_SUB_H` at y `AE_SUB_Y` 29, the same 26 px pitch as the library rows), both from x `AE_TEXT_X` 16 (Search's text-only rows' `SE_REC_TEXT_X`, the hairline too, to `SE_SEP_END`), cut with an ellipsis at 276; the grey line (`Source · Kind[ · Target]`), the hairline, and at x 284 a 22 px glyph centred in the row: the download arrow, a ring (a quarter turn open, one 45° step every 3 ticks) or a white check. The glyphs are drawn at open (`ae_make`: Lucide's shapes by 4 x 4 samples, as the chevron is), three bitmaps freed with the page. Neutral greys, no accent. Strings (13 languages): the card and note, `Downloading List…`, `Downloading…`, `Saved to EQ · Tap to use`, `In use`, `Over-ear`, `In-ear`, `Earbud`; the failure words, `Try Again`, `No Results`, `All`, `Search` already existed. Deviations from the mockup: no percentage (a preset is 0.5 KB; the ring is indeterminate), the target after the kind, and a list that is still downloading shows the state line with no keyboard.

**The list on the card:** `/mnt/mmc/.m1plus/autoeq/index.md` (beside the other card caches: `art/`, `covers/`, `podcasts/`), `updated` (decimal clock seconds, written after the rename). **Rule:** a list that is there is used offline and never fetched on a keystroke; one that is not is downloaded when the page opens (the keyboard stays down, "Downloading List…", then up); one older than 30 days (`PN_EQ_MAX_AGE`), with no date, or dated in the future is downloaded again **in the background** when the page opens (the old one serves; a failure is silent; a clock never set judges nothing). The download is the update's way: a part file, only a body that starts with `# Index` (checked as the bytes arrive, so a heading split over several writes is fine; a body that ends inside it fails) and is at most 3 MB, renamed over `index.md` (a failure removes the part and keeps the old list). A failure (No Wi-Fi, Can't connect, Server error, Certificate problem ... as the Podcasts' words) shows its word with a grey **Try Again** under it; a tap on the page or the keyboard's action key asks again. Back and reopen asks again too. A list that vanishes while the page is open is fetched again.

**Search** (`ae_scan`): the file is read again in 2 KB pieces for each query (nothing of the index is held: 128 MiB memory, 3 MB limit; the page keeps at most `AE_MAX` 20 results, 8 KB of heap, and the 22 / 44 px bitmaps). Lines are looked at as they stream: the words are tested on the name span first (most lines end there), then `ae_parse` builds the entry. Every word of the field (at most 4, 31 bytes each) must be a case-insensitive (ASCII) substring of the name, from any source. Tier 0: the name is the query (the words joined by single spaces), 1: it starts with the first word, 2: the rest; inside a tier the file's order (names sorted). A line over 255 bytes (the longest in the index has 219), the heading and the prose are not results; a name is cut at 63 bytes on a character boundary. Cost (emulated payload instructions, a 9,000 line list): 21-39 M a query, after the 200 ms debounce (about the Search page's own first scan on a 5,000 song library).

**Download.** A tap on a result that is not saved (one at a time; the Podcasts' downloads are asked to pause, as every job of ours does) starts `pn_eq_get(path, stamp)`: `PN_KIND_EQ` in the one job slot (`pn_job_busy`; a second job is `PN_BUSY`), https only, verification on, the firmware CA bundle, the app's user agent, a part file (`/mnt/mmc/.m1plus/autoeq/preset.part`: the stamp line, then the file, at most 16 KB with the stamp: the parser's limit). The path is checked first (`pn_eq_path_ok`: `Source/Kind/Name`, printable ASCII, no space, dot segment, `?`, `#`, quote or backslash, under 400 bytes; a stamp over 400 bytes) because the index came off the network. The row shows the ring and "Downloading…" at once; a tick (40 ms, the page's one timer) starts the worker when the slot is free and reads its state. The page then parses the part with the Equalizer's parser (`peq_import_file`) and **only a file that parses** is renamed into `/mnt/mmc/EQ` (made when missing); else "Cannot read this preset" and nothing is kept. A failure shows the failure word in the message box and the row as it was (no stuck progress: libcurl's time-outs end a request the Wi-Fi dropped, the worker always ends its job, and the tick that sees it stops the timer). Back or Now Playing while a job runs cancels it (`pn_cancel`); its part file goes with the next job.

**Names.** The first line of the file is `# AutoEq: <path>` (a comment: both parsers skip it). A Save over such a file rewrites the line as `# AutoEq edited: <path>` (also a comment), so an edited file is no longer the result's: it is not found as saved, and a tap downloads the original to the next free name (`<Name> (<Source>).txt` ...; the edited file is stamped, just not with this stamp, so it is skipped and never overwritten). A result is **saved** when a file with exactly that stamp exists under one of its names, in order: `<Name>.txt`, `<Name> (<Source>).txt`, `<Name> (<Source> 2).txt` ... up to 9 (every name is looked at, so a stamped copy past a free name is found; the first free name is the download's; an unstamped file of the same name, the user's, is never overwritten). So a headphone from another source, or another target of the same source (the Rtings B&K 5128 and HMS II.3 files), gets its own file and each is found again after any search. The name is cleaned for the card (`\ / : * ? " < > |` and controls become `-`, a leading dot `_`, trailing dots and spaces dropped) and cut so that name, suffix and `.txt` stay under `PEQ_NAME` (64) bytes, which the Equalizer page needs to list it, at a character boundary. With the nine names taken by other files a tap says "Storage unavailable" and asks for nothing.

**Tap to use** on a saved result is `peq_select(file)` (peq_ui.c): exactly a tap on its row on the Equalizer page (parse, save the record, switch stock's Equalizer on or have the player reread, a failed save "Not saved"). The row that plays says "In use" (read from the record; read again when the page is back in front). The Equalizer page lists the new file when it is back in front. A finished download is selected the same way, at once (`ae_installed` calls `peq_select` after the rename), so its row says "In use" and the Equalizer plays it; a failed save keeps the file, and the page says "Not saved".

**Settings Files** (Developer > Tools) has a row `playback-eq` (the state record: present or missing).

**Tests:** `test/pod/autoeq.py` (fixture `test/data/autoeq/INDEX.md`, 60 real lines): `parse_tests` (every fixture line against a Python split, the refused lines, the cut), `search_tests` / `search2_tests` (a Python oracle for 14 queries; tiers, the cap, long lines, CRLF), `net_tests` (the two jobs against a scripted libcurl: URLs, options, every failure, Cancel, one worker, bad paths, the date), `list_tests` (open with and without the list, failure words and retry, the age rule, a silent refresh, a vanished list), `rows_tests` / `names_tests` / `fail_tests` (the download, installed files, stamps, names, Tap to use, a file that does not parse, the Wi-Fi lost, a busy slot, a query changed or the page destroyed during a job), `glyph_tests`, `ui_tests` (chips hidden and insensitive, the list's place, touch, keyboard, German), `perf_tests` (PERF=1); `test/pod/peq.py` (lenient parser, the Presets card and page's strings, their fit in 13 languages). Preview: `tools/preview_autoeq.py` (typing, downloading, saved, in use, the list, a failure) and `tools/preview_peq.py` (the page with the card).

**Not verified on a device:** TLS to `raw.githubusercontent.com` with the firmware CA bundle (Podcasts / Cover & Lyrics reach other hosts the same way), the 0.85 MB list over the Wi-Fi (gzip is accepted; the time-outs are 20 s connect, 30 s under 1 kB/s, 120 s total), the time a query takes on the device (about 20-40 M instructions), the drawn glyphs at 1:1, the keyboard staying down while the first list downloads, the page when a Podcasts download is running (it pauses, as for Find Cover & Lyrics), and the rendered rows with the longer languages.

## Preset page (`patch/peqpage.c`, `patch/peqpage.h`)

**Opening.** A file row of the Presets page is `ACT_PEQ_LIB` (two lines, a chevron, 60 px; see "Presets page"). Its tap calls `peqpage_show(file)`: it parses the file with the Equalizer's parser first (a file that is gone or no longer parses: "Cannot read this preset", nothing opens), keeps the preset and `skipped` in a small scratch struct and opens `ui/m1plus_peqpage.bin` through `m1plus.c` `open_page` (`pod_open_peqpage`, `POD_PEQP_PAGE`), which calls `peqpage_opened`. Back returns to the Presets page, which reads the card again (with unsaved edits it asks first). The page takes a touch on a band row (the band page), **Rename Preset** and **Delete Preset** (below).

**The page** is a [cards page](settings.md) of kind `peqpage` (`PEQP_PAGE`, `pod_pages.peqp_items(n, skipped)`, the asset holds every band row and the note): the graph card, a gap, the **Preamp** row (a single piece: the grey value at the right in 18 px, no chevron), a **Bands** header, one two-line row per band that plays (one card: the first a top piece, the last a bottom piece without hairline, the rest middle pieces, `ST.peqp_pieces(n)`), and, when the parser skipped lines, a two-line wrapping grey note under the card ("N lines not supported were skipped.", `peq_error.skipped`; hidden otherwise). The navbar title is the preset's name without `.txt`, cut with an ellipsis (`az_fit`); the back button and Now Playing are stock's.

- **Band rows** use the 52 px card pieces (the mockup's 60 px would have needed new tall pieces). Two lines in the Podcasts cells' size pair (20 px title, 16 px grey; the 21 / 18 of the library rows are for 64 px rows and looked crowded in 52 and 60 px): the frequency (20 px white, box y 5 / 22 high, `pod_label<i>`) and the grey line (16 px `#AAAAAA`, y 28 / 19 high, `pod_sub<i>`). The gain (`pod_value<i>`) is a value as every Settings value row's (copied from `cards_row` kind `value`): 18 px grey `#AAAAAA`, the box the full row high (centred on the row like the chevron), right aligned ending 8 px before the chevron (`band_right()`, text ink at x 278), `BAND_GAIN_W` 76; the label and the grey line stop `BAND_GAIN_GAP` 4 before it. The grey line (`pod_sub<i>`) is "Low shelf · Q 0.7", "Peak · Q 1.41", "High shelf · Q 0.7", with " · L" or " · R" for a band of one side. Rows hold the preset's bands in the file's order. A filter that parsed but is OFF is kept in the record (`enabled` 0) and never plays: it has no row (the page shows what the engine has). Frequency: `N Hz` below 1 kHz (a tenth of a hertz shown when there is one), `N kHz` from it (hundredths, trailing zeros trimmed: `2 kHz`, `1.25 kHz`); gain `+4.8 dB` / `−2.4 dB` (U+2212) / `0.0 dB`, a tenth, rounded away from zero; Q two decimals, trimmed (`0.7`, `0.89`, `10`). The preamp row says the file's `Preamp:` (`−6.2 dB`, with its sign) or, for a file without one, `Auto · −6.0 dB`: the cut the player makes at **48 kHz** (`peq_preamp_gain`, demo only; the player's own number is per rate, a few hundredths of a dB apart). Texts: `Preamp` `Bands` `Auto` `Low shelf` `High shelf` `Peak` and the two skipped-lines forms (13 languages; the Preamp label has 116 px, hence `Vorstufe`, `Предусил.`). A native-speaker pass is wanted.
- **The graph** is a transparent insensitive `view` `pod_graph` (`GRAPH_H` 170) holding seven labels (the scale at the left, `+12` / `0` / `−12`; `100`, `1k`, `10k` under their grid lines and `Hz`; the payload sets the scale's ends to `+18` / `+24`) and painted by **one bitmap**: `peqpage_opened` makes a `GR_W` x `GR_H` (300 x 170) RGBA bitmap once, and the view's `EVT_BEFORE_PAINT` (the minibar's precedent: after `canvas_translate`, before the view's own background, so the labels, its children, paint over it) does one `canvas_draw_image` at x `GR_CARD_X` 10. No timer, no paint-time work beyond the blit, no hook; the bitmap is freed with the page (`EVT_DESTROY`). With no memory for it the card stays empty and the rows are there. The bitmap is the whole card: `#1C1C1E` with the 12 px corners cut in the alpha (antialiased), the grid (the top, 0 dB and bottom lines, the 100 Hz / 1 kHz / 10 kHz lines, neutral greys), a faint fill (14 % white) between the curve and 0 dB, and a 1.5 px white curve, antialiased from the perpendicular distance to the curve. No accent. Cost: the whole open (parse, 249 `peq_response` calls, 51,000 pixels, the rows) is 4.7 M emulated payload instructions, once per open (the test bounds it at 8 M).
- **The curve:** `peq_compile` of the preset at **48 kHz**, `peq_response` of the **left channel** (`l`; a band of one side only shows on its side's page: a right-only band does not appear in the curve), **without the preamp** (as the mockup) and without balance, one point a pixel column: the plot is `GR_PW` 249 columns from card x `GR_PX0` 36, `GR_DECADE` 83 px a decade from 20 Hz to 20 kHz (column `c` is 20 Hz x 10^((c + 0.5) / 83)); rows `GR_PY0` 9 .. +138, the 0 dB line the middle row. **Range:** ±12 dB, extended to ±18 and then ±24 when the curve passes it (the labels change; a curve past 24 is clamped to the plot's edge). dB is `pp_db10` (a series log: the payload has no libm `log`), within 1e-5 dB.
- **Delete Preset** (`ACT_PEQ_DELETE`, `pod_row31`, the last card, always shown): red label, no glyph, no chevron. A tap asks the stock confirm dialog ("Delete Preset?", as Delete Playlist does; yes is `CONFIRM_YES`). Yes: `peq_delete` (`patch/peq_ui.c`) unlinks the file; when it is the preset that plays, the record is rewritten at Graphic EQ and stock's Equalizer is switched off (`pq_set_flag(0)`: the flag, its save and `set_equalizer_value`). Then `window_close(pg.win)` returns to the Presets page (not `navigator_back()`: the confirm dialog is still closing when the modal call returns, so it is the top window). A file that cannot be unlinked shows "Failed To Delete Preset" and the page stays.
- **Deviations from `1-preset-detail.png`:** no toggles (the gain sits at the right edge, where the toggle was; no chevron on the Preamp row, which is not tappable); rows are 52 px, not 60 (the grey line is 16 px); the preamp is "Auto" only when the file has no `Preamp:`; the frequency labels use `kHz`; the scale reads ±18 / ±24 for a stronger curve.

**Tests:** `test/pod/peq.py`: `preset_page_tests` (the rows, every string of shelf / peak / one side / kHz / zero / Auto / one skipped line, the pieces and hairlines, the scale for 12 / 18 / 24 / a clamped curve, the bitmap against `tools/peq_graph.py` pixel by pixel with a tolerance of 2 grey levels and 1 alpha level, the brightest pixel of each of the 249 columns against the test's own RBJ model of `peq_response`, the corners' alpha, the grid, one blit in the before-paint and nothing else, destroy, no memory for the bitmap, the refused files, a page that is not ours), `page_tests` (a tap at any x on a preset row selects it, the Presets card opens the Presets page, a file that does not parse, Graphic EQ), `presets_page_tests` (the Presets page: AutoEq and On Card sections, grey lines, pieces and hairlines, the 64-file cap, the taps, Delete Preset: confirm, unlink, the record and the flag when it plays, the failure), `layout_peqlib_tests` (demo's layouter on the Presets page and the asset), `layout_peqp_tests` (demo's layouter and hit test on the preset page for 1, 4 and 30 bands with and without the note, the Delete card), `widths_tests` (13 languages), `asset_tests` (the rows, the check and the Presets card of the Equalizer page). Preview: `tools/preview_peqpage.py` (`out/preview/peqpage.png`: a long and a short preset, the Equalizer page with its chevrons).

**Not verified on a device:** the Presets page and its return from a Preset page (the re-read on Back), the Delete dialog and unlink on the card, the tall rows' art at 1:1, the before-paint blit under the labels and its clipping at the list's edges while scrolling, the graph's look at 1:1 (the antialiasing, the fill's strength), the time to open the page, a preset with 30 bands scrolled, and the longer languages.

## Presets page (`patch/peqlib.c`, `patch/peqlib.h`)

Opened by the Equalizer page's Presets card (`peq_ui.c` `peqlib_open`, `patch/m1plus.c` `pod_open_peqlib`, `POD_PEQLIB_PAGE`): a cards page of kind `peqlib` (`PEQLIB_PAGE`, page 53), navbar Back, title "Presets", Now Playing. It has no search, no enable switch and no "On" labels.

- **Download from AutoEq** (`ACT_PEQ_AUTOEQ`, `pod_row0`): a card of its own, `autoeq_open`.
- **AutoEq** (header `pod_sec0`, hidden while empty): the files whose first line is `# AutoEq: <path>` or `# AutoEq edited: <path>` (`peq_list` order), each a 60 px row (`ACT_PEQ_LIB`, `LIB_ROW_H`, the tall card pieces `pod_cdl_*`): the name without `.txt` (`pod_label<i>`, 20 px, box y 8 / 22 high), the grey line `Source · Kind` (16 px, y 32 / 19 high, the same sizes as the band rows) (`pod_sub<i>`; the kind is the directory's end: Over-ear, In-ear or Earbud, else the source alone; the source is shown percent-decoded, "Super Review", while the stamp keeps the encoded path as the file's identity), a chevron.
- **On Card** (header `pod_sec1`, hidden while empty): every other file, grey line "On card".
- The asset has `PQ_ROWS` slots per section (rows 1 to 64 AutoEq, 65 to 128 On Card). The payload shows as many as there are, sets each section's pieces (single, top, middle, bottom) and hairlines, and sets `virtual_h` from the model (`POD_LIB_BASE`, `POD_LIB_HDR`, `POD_LIB_ROW`). Each file is read at most three times per layout (the first line only).
- A tap on a file row: `peqpage_show(file)` (the Preset page). Back in front (`EVT_WINDOW_TO_FG`): the card is read again, so a download or a delete shows at once.
- The list keeps `PQ_ROWS` (64) files in all, as the Equalizer picker does (`PQ_ROWS` is one constant in `patch/offsets.inc`, mirrored by `PEQ_ROWS` in `tools/pod_pages.py`); the Equalizer's Presets count is every `.txt` on the card, so it can be larger.
- Strings (13 languages): Presets, AutoEq, On Card, On card, Delete Preset, Delete Preset?, Failed To Delete Preset.

- **Row limit:** every row is a widget baked into the asset (the payload only names, shows and hides them), so `PQ_ROWS` costs asset size: the Equalizer asset 44 KB and the Presets asset 101 KB at 24 rows, 105 KB and 262 KB at 64. A runtime clone of one template row (AWTK `widget_clone` in the statically linked demo, inserted with `widget_restack`) would make the limit free, but `widget_clone` is not pinned in `tools/pod.py`, each row has to be renamed child by child (`pod_label<i>`, `pod_sub<i>`, `pod_hair`, ...) and the emulator tests have no model of it; not tried. Raising the limit again is the constant change plus the test file counts.

## 10-Band EQ

Our own ten-band EQ replaces stock's slider page (`playset/equalizer_page`): ten octave bands, stock's genre curves as presets.

**What the user sees.**
- **Equalizer page:** the picker's first row is **10-Band EQ** with the curve's name in grey before the check
  (`Rock`, `Custom`); a tap only picks it, as every picker row. The bottom card holds two link rows: **10-Band EQ** (grey curve name,
  chevron: opens the editor) and **Presets** (count, chevron), one card.
- **Editor** (title "10-Band EQ"): a **Curve** row card at the top (grey curve name, chevron: the Curve page), then the Preset page's graph card (the curve of the ten bands with the preamp left out, as the Preset
  page), the region line's box (`REGION_H` 30: the 18 px line centred, 6 px clear above and below it), a card of **ten vertical sliders** (31, 63, 125, 250, 500, 1k,
  2k, 4k, 8k, 16k Hz under them, the gain above each without "dB": `+4.5`, `−2.5`, `0`), then one card with **Preamp** (grey
  `Auto · −5.0 dB` or `−3 dB`, chevron) and **Reset** (white, plain). The page scrolls (Preamp and Reset sit below the fold: fine).
  Sliders: ±12 dB in 0.5 dB steps; a drag anywhere in a column (about 29 px wide) moves that band, not only on the thumb; while
  dragging, the column's value shows in a white pill and its label turns white, the graph follows. Moving a slider on a built-in curve
  copies that curve into **Custom** (silently overwriting the previous Custom) and the Curve row reads Custom. The sound follows the
  drag (the gain-command reload and its 20 ms ramp), the record is saved when the drag ends.
- **Curve page:** one card, Flat, Pop, Rock, Dance, Blues, Metal, Vocal, Classical, Jazz, Custom; the current one checked; a tap picks it
  (gains loaded, sound follows) and goes back. The genre gains are stock's own table (`demo`'s `reset_user_eq` 12x10 float table, "Genre table" below) copied into the payload; Flat is all zero; Custom is the user's.
- **Preamp page:** **Auto** (grey: the cut Auto makes now, `−5.0 dB` = the largest boost, `0.0 dB` for a flat curve) in a card of its own (a single piece), under it the grey note "Auto reduces the level to help prevent distortion from EQ boosts." (`pod_note0`, two lines at most; its height is the space between the cards), then a card of
  `0 dB`, `−1 dB` ... `−12 dB` (U+2212); checked row; a tap picks and goes back. No positive values. The rows are still `pod_row0` (Auto) .. `pod_row13`, numbered across both cards (`TENPREAMP_PAGE.layout`), so `tenband.c` binds them unchanged.
- **Reset** (editor): sets Flat (all bands 0, Preamp Auto). On Custom it asks first, the stock confirm "Reset 10-Band EQ?"
  (Cancel / OK) because it erases the user's curve; on a built-in curve it resets at once (picking the curve again restores it).
- **Stock's slider page is retired:** the one way into it (stock All Playback Settings > Equalizer) opens our Equalizer page instead; the stock "Not applied to DSD" note goes with the page.
- Neutral look only (no accent), same card pieces, rows, hairlines, chevrons and navbar as the other EQ pages.

**State.** The record holds the ten gains, the curve id (Flat .. Jazz, Custom), the Custom gains and the preamp choice (Auto or
0..−12 dB); the 10-Band mode plays our gains (ten RBJ peaking bands, 31 Hz-16 kHz, Q 1.41) plus the preamp.
A missing or older record starts as Flat. Stock's `equalizer_flag` (the Equalizer switch) stays the on/off.

### Record, player and Equalizer page

- **Record** (`patch/peq.h`, `patch/peq.c`): `peq_state` has `curve` (`PEQ_FLAT`, `PEQ_POP`, `PEQ_ROCK`, `PEQ_DANCE`, `PEQ_BLUES`, `PEQ_METAL`, `PEQ_VOCAL`, `PEQ_CLASSICAL`, `PEQ_JAZZ`, `PEQ_CUSTOM` = 0..9),
  `preamp` (`PEQ_PREAMP_AUTO` -1, or 0..12 for 0..−12 dB), `gain[10]` (what plays) and `custom[10]` (the user's, kept while a built-in curve plays); magic `M1PEQ02`; a missing or old record is Flat, Auto (stock's gains are not read). The mode of the 10-Band EQ is `PEQ_TENBAND_MODE`; `PEQ_FILE` plays a preset file, and selecting a file keeps the 10-Band fields.
  Invalid: curve outside 0..9, preamp outside -1..12, a gain (either array) outside ±12 dB or not finite; `peq_state_save` refuses it, `peq_state_load` reads it as none.
- **API for the editor** (demo only): `peq_curve_gains(s, curve, out)` (the ten gains of a curve; `PEQ_CUSTOM` gives `s->custom`), `peq_set_curve(s, curve)` (sets `curve` and loads `gain[]` from it). A slider move on a built-in curve is the editor's to do: copy `gain[]` into `custom[]`, `curve = PEQ_CUSTOM`, change the band, save with `peq_state_save`, then
  `set_equalizer_value(EQ_MODE)` as `pq_commit` does (it makes the player reread the record: the 20 ms ramp). During a drag, saving each step is possible (the player reads on each gain command); the spec saves at the end.
  `peq_curve_key(curve)` (`patch/peq_ui.c`) is the English key of a curve name (`widget_set_tr_text`). `peq_tenband(p, gain, preamp)` (shared, the player's too) builds the preset the player plays.
- **Player** (`patch/peq_player.c`): `effective()` reads the record each `REINIT` and each channel-0 gain command; mode 0 (or no record) = `peq_tenband` of the record's `gain[]` and `preamp`: ten peaking bands 31 Hz..16 kHz,
  Q 1.41; preamp Auto = the engine's Auto (`automatic` 1: minus the response's own peak per rate, never a boost; for the largest band boost of a smooth curve this is within a dB of it, not equal), a fixed value = `automatic` 2 with
  `preamp` -N dB. Flat with Auto leaves audio bit-exact. The carried filter memory compares the whole preset, so a curve change at a join is a fresh start as before.
- **Equalizer page** (`patch/peq_ui.c`): the first picker row is 10-Band EQ with `pod_value1` (a grey curve name, box `pod_settings.curve_box`, always shown, even while a preset plays); the bottom card is `pod_row66` 10-Band EQ
  (link, grey curve name `pod_value66`) and `pod_row67` Presets. `pq_on_tenband` (`patch/peq_ui.c`) opens the editor. Back in front re-reads the record, so the names follow the editor's changes.
  Presets is row `PQ_N + 1` (`pod_row67`, `pod_value67`), `peq_pieces(n)` excludes both bottom rows.
- **Settings > Playback > EQ** shows `Off`, the file name, or the curve name (Flat, Rock, Custom ...; Flat with no record), the stock preset name is gone (`peq_playing_name` always answers).
- **Strings** (13 languages, `tools/pod_i18n.py`): `10-Band EQ` (replaces `Graphic EQ`), `Edit 10-Band EQ`, `Curve`, `Custom`, `Flat`, `Pop`, `Rock`, `Dance`, `Blues`, `Vocal`, `Classical`, `Jazz` (`Metal` is the Cassette theme's key), `%d dB`
  (the payload writes U+2212 before a cut; value form of the Preamp rows) and `Reset 10-Band EQ?`; the Reset row uses the `Reset` key of Developer > Reset. The genre names are ours, not stock's `eq_*` keys: stock's tables are poor in fr / it / ko / th
  (Roche, Le jazz, English words, a duplicated Rock/Dance). Translations are mine (a native-speaker pass is wanted); the 10-Band EQ label is short in es / pl / ru / uk (`EQ 10 pasm.`) to fit its 128 px.
- **Genre table** (verified, V2.1 `demo`): `reset_user_eq` (`0x4d8490`) `memcpy`s `0x1e0` bytes (12 x 10 floats) from `0x74b5bc` into a stack buffer and stores `row[mode] + 6.0` (the float at `0x747274`) into the user table
  `0xa0c588`; `set_equalizer_value` (`0x4d851c`) sends `user[mode] - 6.0` for modes 1..11. `get_equalizer_preset_name` (`0x49daec`) indexes the pointer table `0x97c7a0` (`close`, `eq_custom1..3`, `eq_pop`, `eq_rock`, `eq_dance`,
  `eq_blues`, `eq_metal`, `eq_vocal`, `eq_classical`, `eq_jazz`: entry k is mode k), so rows 4..11 are the genres, rows 0..3 are all zero. dB for 31, 63, 125, 250, 500, 1k, 2k, 4k, 8k, 16k:
  Pop 3 1 0 -2 -4 -4 -2 0 1 2; Rock -2 0 2 4 -2 -2 0 0 4 4; Dance -2 3 4 1 -2 -2 0 0 4 4; Blues -2 0 2 1 0 0 0 0 -2 -4; Metal -6 0 0 0 0 0 2 0 2 0; Vocal -4 0 2 1 0 0 0 0 -4 -6;
  Classical 0 3 3 2 0 0 0 0 1 1; Jazz 0 0 0 2 2 2 0 1 2 2. `test/pod/peq.py` `parser_tests` compares our table with the stock `demo` binary's rows at `0x74b5bc` on every run. The names' order and the gains agree
  with the genres (a Metal low cut, a Pop mid dip, ...), checked by reading, not by listening.

### Editor, Curve and Preamp pages

**Files.** `patch/tenband.c` / `tenband.h` (the three pages), `patch/peqpage.c` (the graph code, shared), `tools/tenband_model.py` (the slider card's model), `tools/preview_tenband.py`, tests `tenband_drag_tests` to `tenband_preamp_tests`, `layout_tenband_tests` and the 10-Band part of `widths_tests` in `test/pod/peq.py`.
Three cards pages of kinds `tenband`, `tencurve`, `tenpreamp` (`TENBAND_PAGE` 54, `TENCURVE_PAGE` 55, `TENPREAMP_PAGE` 56, followed only by AutoEq and the band page in `PAGES`; no exported rows, the payload binds them by name; `POD_TENBAND_PAGE` etc.). New row actions
`ACT_PEQ_TCURVE`, `ACT_PEQ_TPREAMP` (kind `wvalue`: a grey value `PREAMP_W` 150 wide before the chevron, label box 98 px), `ACT_PEQ_TRESET` (kind `plain`), `ACT_PEQ_CPICK`, `ACT_PEQ_PAUTO`, `ACT_PEQ_PVAL` (`check` kinds; Auto carries a grey value
with `curve_box` like the Equalizer page's 10-Band EQ row; the thirteen `0 dB .. −12 dB` rows have no text in the asset, the payload writes it with `%d dB` and a U+2212 before a cut). `item Sliders` / `SLIDERS_H` 170 is the slider card's layout item.

**The editor** (`tenband_open` from the link row, `pod_open_tenband`): a Curve row card (`pod_row0`, `pod_value0`) at the top, the graph card (`peq_graph_*` of `peqpage.c`: `peq_tenband` with a fixed 0 preamp so no peak search, `peq_compile` at 48 kHz, the same ±12 / ±18 / ±24 scale), the region line's box (`pod_regionbox`), the slider card (`pod_sliders`), then Preamp (`pod_row1`, `pod_value1`: `Auto · −5.0 dB` from `peq_tenband` + `pp_preamp`, or `−3 dB`) and Reset (`pod_row2`). It loads the record when it opens and when it is back in front (after the Curve or Preamp page), changes its copy
and saves with `peq_commit` (`peq_ui.c`: `pq_commit`, so a failed save shows "Not saved" and the page reloads the record; stock's Equalizer is switched on if it was off, and the gain command is sent). **Decision:** any edit, Curve pick, Preamp pick or Reset also sets the mode to the
10-Band EQ (and clears the preset file's name): a preset that played is dropped, because the user could not hear the edit otherwise (the Equalizer page's check follows when it is back in front). Reset on Custom asks `peq_ask` ("Reset 10-Band EQ?", the stock confirm shared with Delete Preset);
it zeroes `gain[]` and `custom[]`, Flat and Auto; on a built-in curve it asks nothing, sets Flat and Auto and keeps `custom[]`.
**Region line and replace message.** Between the graph card and the slider card the layout item `REGION` (a `REGION_H` = 30 px box, `pod_settings.py`) holds the empty 18 px grey label `pod_region` (`cards_region`), centred in the box so it has room above and below. While a band is dragged it reads that band's region (`tb_region`; keys `Sub bass · rumble` 31 Hz, `Mid bass · punch and warmth` 63 / 125, `Lower mids · body and fullness` 250 / 500, `Upper mids · shouty if too much` 1k / 2k / 4k, `Treble · detail and sparkle` 8k, `Air · openness` 16k), set at DOWN, cleared at the release (UP, abort); each translation fits 272 px (`widths_tests`; ru / uk / pl use short forms such as `Низ. середина`). The move that switches playback from a preset file to the 10-Band EQ sets `tb.replaced`; at the release the stock message box says `Switched to 10-Band EQ` (`pod_toast`, once per switch; not when the 10-Band EQ already played, not when the save failed). It waits for the release because the message box is a window that opens over the page and would take the grab mid-drag (not tried on a device).
**Opened twice.** An editor can be opened while another sits under Now Playing (pull-down > Playback Settings > Equalizer). `tenband_opened` then frees the old editor (its bitmaps and graph) and closes its window, the way the Radio pages do (`rn_open`); every destroy handler is bound with its own window as context, so a replaced window's late `EVT_DESTROY` finds `tb.win` changed and leaves the new editor alone. The Curve and Preamp pages (`tc`, `tp`) do the same. Tests: the "opened twice" parts of `tenband_reopen_tests` in `test/pod/peq.py`.

**The sliders** are one transparent sensitive view painted in its `EVT_BEFORE_PAINT` (the graph's way): the card bitmap with the ten tracks baked in (made once), a thumb bitmap blitted per column at the band's height and, while dragging, a pill bitmap behind the value. Values (`pod_sl_v<c>`, 11 px, empty in the asset)
and frequencies (`pod_sl_f<c>`, `31 .. 16k`) are labels painted over it; while dragging the value is black (on the pill) and the frequency white (`style:<state>:text_color` set through `widget_set_prop_str`, back to grey at the end). Geometry: `TB_*` in `patch/offsets.inc` (column 29 px from card x 5,
track y 40 .. 136 = ±12 dB at 4 px a dB, 2 px a half-decibel step, thumb 24 x 13, pill 34 x 18). Touch maths (`tenband_col`, `tenband_step`, tested against `tools/tenband_model.py`): the column is `(x − 5) / 29` clamped to 0..9 (a touch in the 10 px beside the card does nothing); the step is
`(88 − y) / 2` truncated toward zero, clamped ±24, so 0 dB takes the three pixels around the middle. The column is latched at DOWN and the band is set to the finger's height at once; moving sideways keeps the column.

**Drag against scroll.** The page is a `scroll_view` that reads a vertical drag of 10 px as a scroll (`docs/modules/gestures.md`). The view's DOWN handler does `widget_grab(window, view)` (the A-Z rail's way, `patch/azlist.c`): the window's `widget_find_target` returns its grab widget at once, so the gesture's MOVE and UP reach the view
wherever the finger goes and the list_view / scroll_view never see them, so nothing scrolls. As a second guard, if the scroll_view still took the gesture (the grab not diverting it), `yslidable` is set to 0 for the gesture (`widget_set_prop_int`, restored from the saved value at UP, ABORT, back in front and destroy), which stops `scroll_view_is_dragged`
and with it the scroll and the abort. A DOWN on a coasting list is eaten by `patch/scroll.c` (that touch only stops the list; tap again). The rest of the page (graph, rows, the margin beside the card) scrolls as any cards page. **Not verified on a device**: that the window-level grab really diverts a gesture that begins inside a scroll_view's child (the emulator
tests assert the calls, not AWTK's dispatch); if it does not, `yslidable` = 0 still blocks the scroll but the view's MOVE then depends on AWTK's target logic.

**Costs.** A band step that changes the value moves the thumb and the value label (cheap). ## Per-output EQ (`patch/peqout.c`, `patch/peqout.h`)

**What the user sees.** Headphones, Line Out and a USB DAC each keep their own EQ: Off or on, the 10-Band EQ's curve, gains and preamp, or a preset file. It switches by itself when the output changes, also while a track plays (the player rereads within a block, the usual 20 ms ramp). The Equalizer page says which output it edits in a grey line under the switch card ("For Headphones", "For Line Out", "For USB DAC"); every edit (the page, the 10-Band editor, a preset page, AutoEq's Tap to use) applies to the output playing now. No setting. Bluetooth is not an output of its own: it keeps the headphone EQ (the user does not use it; it falls out as `way` 1 -> Headphones).

**Design.** The player still reads one record, `playback-eq` (the *playing* record); nothing in `peq_player.c` changed. Beside it, in the settings folder: `playback-eq-headphones`, `playback-eq-lineout`, `playback-eq-usb` (the same `M1PEQ02` record, one per output, a *slot*) and `playback-eq-output` (`M1PEQO1\0`, the output the playing record belongs to, and each output's setting of stock's Equalizer switch). `peqout_sync(notify)`: when the output differs from the last one seen, (1) the output file's `on[owner]` takes stock's switch, (2) the playing record is filed in the old output's slot (a missing or invalid playing record is never filed over a slot), (3) the new output's slot, if there is one, becomes the playing record (`peq_state_save`, atomic), (4) the switch is set to what that output had (`EQ_FLAG`, `write_int_config`, `set_equalizer_value`), (5) the owner is written. An output with no slot keeps what plays and the switch as it is. A failed filing or load stops before anything changed and is tried again at the next call. The owner file is written last; if that write fails the playing record is put back from the old output's copy (or removed when even that fails, and a missing record is never filed over a slot), so one output's curve is never attributed to another, and the next call tries again. A Rename Preset also rewrites the name in every slot that names the file (`peqout_renamed`). Atomic file helpers: `peq_state_load_from` / `peq_state_save_to` (`peq.c`; `peq_state_save` is `PEQ_STATE` through them, `playback-eq.tmp` became `<path>.tmp`).
**First run.** The playing record needs no migration. The first `peqout_sync` only writes the output file (owner = the output now, every output's switch = stock's switch), so the same EQ plays on every output until one is edited; the first output change then files it as the old output's slot and the new output starts from it.
**Switch rule.** Saves, Save As and Revert never switch stock's Equalizer on by themselves; the per-output switch is part of an output's remembered choice (Off on Line Out, on for Headphones), so on an output change stock's switch is set to that output's last setting both ways, and only on a change. A switch that a change never turns on would be the `flag = r.on[cur]` line in `peqout_sync`.

**Detection.** `peqout_current()`: `mclGetOutputWay()` (`0x5d45a4`, the same call `patch/radio.c` makes: 0 the built-in DAC, 1 Bluetooth, 2 USB audio) is 2 -> USB DAC; way 0 and stock's Line Out byte (`0xa05aa7`, `LINEOUT_FLAG`, the byte the Line Out pill tests) set -> Line Out; else Headphones (3.5 mm and 4.4 mm alike, and Bluetooth). Confidence: high for the Line Out byte (`LINEOUT_PINS` pin the code that reads it), medium-high for USB (radio.md's output-way notes and the Q2 EQ's `mclGetOutputWay() == 2`; not tried on a device).
**Where it runs** (no new hook): `lo_set_text` (`lineout.c`, the status bar's one second timer on every page, notify 1: it also sends `set_equalizer_value` while the switch is on), `rd_save_start` (stock's `save_start_player`, an output changed under a track) and `rd_start_player` (`mclStartPlayer`, a track starts, screen off too; both notify 0), and the Equalizer page when it opens and when it is back in front (`peq_ui.c`). The same one-int-compare early exit in each (`po.known`, `po.cur`), no file access when the output did not change; the kill switch (`/mnt/mmc/m1plus-off`) makes it do nothing; a one-flag guard stops two threads switching at once. Not on the boot path.

**Files.** `patch/peqout.c`, `patch/peqout.h`, `patch/peq.c` (`peq_state_load_from`, `peq_state_save_to`), `patch/peq_ui.c` (the line, the sync on open and on return), `patch/lineout.c`, `patch/radio.c` (the three call sites), `tools/pod.py` (`LINEOUT_FLAG`, the source), `tools/pod_pages.py` (`PEQ_OUTPUT`: the Equalizer page's first note, so the hint is `pod_note1`, the DSD note `pod_note2` and the gap before the bottom card `pod_gap0`), `tools/pod_i18n.py` (three strings, 13 languages), tests `output_tests` in `test/pod/peq.py` (detection, first run, a round trip Headphones -> Line Out -> Headphones -> USB, switch both ways, notify, kill switch, failed filing, damaged files, `rd_save_start`, the page's line) plus small checks in `test/pod/lineout.py` and `test/pod/radio.py`, preview `tools/preview_peq.py` (shows the asset's "For Headphones"; the other two are the payload's text).
**Limits.** The Settings Files page lists `playback-eq` only (the playing record, see Settings Files above); the four per-output files (`playback-eq-headphones`, `-lineout`, `-usb`, `-output`) are not listed (Reset All Settings removes them with the rest of the folder). An output change under open pages: when `peqout_sync` switches with notify (the status bar timer) it calls `peq_output_changed` (`peq_ui.c`), which reloads the record and redraws the Equalizer page (the grey line, checks, curve names) and the 10-Band editor (`tenband_output_changed`); a switch without notify (the player thread's hooks) leaves `po.pending`, and the UI thread's next call does the same refresh; a touch on the editor's sliders also rereads the record first, and the Equalizer page's 10-Band EQ row, the Curve and Preamp pages, Save as Preset and the Preset page's commit all read the record at the moment of the tap, so no page writes a stale copy over the new output. A Preset page (band editing) keeps its preset file and unsaved edits across the change. The edit session remembers its **owner**, the output playing when a live edit was last committed (`pg.owner`, a token from `peqout_session()`; the next live edit after a change makes the new output the owner). **Routing.** `peqout.c` alone decides whether a write goes to the playing record or to an output's slot; callers state intent: `peqout_session()` (take the owner), `peqout_away(session)` (syncs, then: did the output change since), `peqout_session_filed(session, from, to, preset)` (the owner's slot) and `peqout_playing_filed(file, preset)` (the playing record), `peqout_renamed` / `peqout_deleted` (every slot), `peqout_sync` (record <-> slot on an output change). After a change, Don't Save and Save never touch the record or playback of the output playing now: they act on the owner's slot through `peqout_session_filed` (only when that slot is in file mode and names the preset; a failed write shows "Not saved" and the page stays unsaved). Don't Save puts the file's preset into the owner's slot; Save writes the file (shared by all outputs), puts the saved preset in the owner's slot and updates the record playing now only when it already names this file; Save As moves the owner's slot to the new file. **Delete Preset** also clears every output slot that names the file (`peqout_deleted`: the slot points at the 10-Band EQ and that output's switch goes off, as for the playing record; "Not saved" when one cannot be rewritten), so no output brings the file back. Bluetooth cannot have its own EQ. No per-device USB profile.
**Open device checks.** Line Out on/off in Settings and the Output tile: the line flips within a second and the sound follows during playback; the amber LO pill and the EQ agree; a USB DAC plugged in mid-track and unplugged; 3.5 mm to 4.4 mm (same profile, no click); headphones unplugged and plugged with the screen off (the profile at the next play); a gapless join across a Line Out switch (a normal reload: the carried memory only joins an identical preset); the switch following the output (Off on Line Out, on for Headphones); no stale `Not saved` toast; first boot of this build keeps the old EQ everywhere.
