# Artists

**Sources:** `patch/artists.c`.

**Genres and Composers are the same page** (`ACT_ARTISTS` with the row's stock Home tile as its argument: `artists_open(0)` Artists, `HOME_GENRE` 7, `HOME_COMPOSER` 8; `ar.cls` is the stock class listed: `0xf004`, `0xf006` `getAllGenre` (`select id,style from songtable group by style COLLATE NOCASE`), `0xf005` `getAllComposer`). - **Sections**: `ar_sections` gives every display position the rank of `cc_name_initial(name)` (the first byte of the text the sort compares: `so_name` of `patch/covercache.c`, white space, then a leading run of punctuation (when a letter or digit follows it) and a leading `The ` dropped, so "The Beatles" and "(What's the Story)" file under B and W; a CJK character is its pinyin initial, a kana its romaji initial and an accented Latin letter its base letter), `az_rank_of` (a letter A..Z either case; a digit, a symbol and every name in another script with no initial are "#", rank 0), and `az_sections` (`docs/modules/songs.md`, the non-decreasing labelling that puts the most rows under their own letter; the list keeps its order, a row out of place stays in the section around it, at most 27 sections, no memory = a plain list with no headers and no rail). **Artists** are sorted by `ar_sort` (below) and so are in letter order but for "Unknown Artist" and digits, symbols and other scripts with no initial (Hangul, Cyrillic, Greek, × ÷; first, under "#"); an accented Latin name (Ólafur, Éric, Ångström) files under its base letter; **Genres and Composers keep the stock order** (the in-memory title sort above; the "Unknown Genre" / "Unknown Composer" row last) and take the same labelling, so no second order is made. **Name Z-A** (`ar.rev`) mirrors all three: the sorted rows are reversed, the Unknown rows keep their stock (last) positions, and the ranks are mirrored so they still rise down the list (Z 0 .. A 25, "#" 26: digits, symbols and the scripts with no initial last), the headers and the rail read the letters back (`sec_letter`), so the rail and the headers run Z to A and "#" is last. The Name order is the only one: there are no counts to sort by (below), so the rail is always there with sections; a list with no sections (no memory) hides it, hidden and insensitive, as before. **The "Unknown ..." row (id -1) takes the rank of the row before it**: it is last in stock, would be a stray by its own letter and, as the last row of a run of one-row sections (a tie), could swallow the section of the row before it (a lone Z artist). The rail and the pinned header are `az_*`, unchanged: `sg_rail` at x 284, 36 wide, the compact A-Z plan, the grab and jump (to section i's header, clamped; the first section to the top, the large title with it), the bubble.
- **Order and the album Artist rule**: the order is the album Artist order's name rule, applied by `ar_sort`. The stock lists are sorted in memory by `toolsQueryDbTable` (sort 1, `algo_sort_if`, comparator `0x5e0dac`; not by the SQL `group by`), which orders by the title's first byte, comparator 0x5e0dac (class checks after 0x5e1104, return paths 0x5e12cc..0x5e13b0 and 0x5e1684..0x5e16c0): digits first; then ASCII letters and CJK (lead bytes E4..E9, by pinyin); then other non-ASCII (such as ÷, C3 B7); then lead byte E3 (kana, CJK punctuation); then EA..EC (Hangul); then E0; then `{|}~`; then `[\]^_` and the backquote; then `:;<=>?@`; and last 0x00..0x2F (space and ``!"#$%&'()*+,-./``); inside a class `strcasecmp` (digits: numeric prefix compare) (so stock puts symbol-led names after Z, not before the letters; our keys put them first under "#"): digit runs as numbers, `strcasecmp`, a CJK name through `utf8_to_pinyin` (`0x73a5f0`, `docs/modules/songs.md` "The Initial"). `cc_name_keys` of `patch/covercache.c` makes one key per name once per sort (the name without leading white space, without leading punctuation (`so_name`: a run of ASCII punctuation and of these opening / quote marks, with white space between, skipped only when a letter, a digit or a non-ASCII character outside the list follows: ¡ ¿ « » ‘ ’ ‚ “ ” „ ‹ ›, CJK 〈 〉 《 》 「 」 『 』 【 】 and full-width ( ) [ ] { } " '; "(What's the Story)" is W, "¡Viva" V, "「すずめ」" S, "+44" the digits 44; a name of punctuation only such as "!!!" or "÷" keeps it, under "#"; the copy never grows) and a leading `The ` (also after the punctuation), or a copy where each CJK character is its pinyin initial, taken by calling stock's `utf8_to_pinyin` on that one character, and each kana (hiragana U+3041..U+3096, katakana U+30A1..U+30FA, lead byte E3) its Hepburn initial from `kc_kana` (86 bytes, one per hiragana; katakana is hiragana + 0x60; し S, ち C, つ T, ふ F, じ ぢ J, づ Z, を O, ヴ ヷ..ヺ V, a small kana with its row, ー and the iteration marks none), so ヨルシカ files under Y; each accented Latin letter of U+00C0..U+017F (lead bytes C3..C5) becomes its lower-case base letter from `kc_latin` (192 bytes, one per code point, space = none: × ÷ stay symbols; from the Unicode decomposition plus ß s, æ œ ø ð þ ł đ ı and the like by hand; 2 bytes become 1, so a copy never grows), so Ólafur Arnalds files under O and Beyoncé sorts as "beyonce", and Éric ties with Eric on "eric" (stock order); a block of 4 bytes per name plus the copies, one `calloc`), and `cc_key_cmp` compares keys: digit runs by value (leading zeros ignored), then per byte digits before symbols (every non-ASCII byte is one, by its UTF-8 bytes) before letters, ASCII case folded; a prefix comes first; ties by stock position (`cc_heapsort`, no libc callback). Stock's second key for equal first initials (the full pinyin, `utf8_2_pinyin`) is not reproduced: CJK and kana names compare by their initials string, other scripts by byte before the Latin names (with the symbols, "#"). `cc_name_cmp` (Radio, podcast and country lists, no initials or base letters: they have no keys pass) takes the same class rule: a non-ASCII name leads, an accented one too. `ar.order[]` (stock row at each display position, `calloc`s of 4 bytes per artist, the scratch arrays freed at once, `order` freed when the list is rebuilt and on close) is built over the copy, so no stock row moves. Every row but "Unknown Artist" (id -1) takes part as one set; the Unknown rows keep their stock positions (stock: last) and the sorted rows fill the other positions in order, so "The Beatles" reaches B wherever a fixed row sits. A failed allocation (order, row pointers or keys) leaves `order` NULL (stock order). `ar_stock` maps a display position to the stock row handed to `coverflow_artist`. The sort re-runs at every `ar_load` (open and the mode toggle). `getAlbumByArtist`, `getAlbumByAlbumArtist` (`0x4eaccc`, `0x4eb0e4`), `getAllComposer` (`0x4ebde8`), `getAllArtist`, `GetAllAlbumArtist`, `getAllAlbum` and `getAllGenre` all pass 1 as `toolsQueryDbTable`'s fourth argument (`addiu $a3, $zero, 1` before the call).
- **Cost against stock's sort**: stock's comparator, run for real under Unicorn on the same names (its libc calls mocked, counted and given rough glibc costs), takes per compare 744 instructions of its own code + ~2,100 of libc on the test's names (`Aa00012`), 1,484 + ~2,800 on library-like names, 1,445 + ~3,100 on CJK names; `cc_key_cmp` takes 148, 128 and 177. Each stock compare clears two 1 KB buffers, `snprintf`s both names, converts them to pinyin and calls `strlen` 18-41 times (in a loop condition); ours converts once per open (`cc_name_keys`, ~0.5 M for 1000 CJK names). A 5000-row sort (~61,000 compares, n log2 n assumed for `algo_sort_if`) is ~170-265 M for stock, 8-9 M for ours. Stock's sort always runs first (`loadLocalClassList`), so the page adds its whole open (20.0 M for 5000 library-like names, 21.2 M for the test's) to well over 10x that. The compare's common prefix is a plain byte loop (folding only bytes that differ) and digit runs are in `kc_runs` (one pass back over the common part, one forward): names that differ only inside a digit run cost 12-18 % more than the old ASCII-fold compare, library-like names 11 % less (22.5 M before).
