# Podcasts

Local episodes, subscriptions, downloads, Apple Podcasts directory search, episode notes
and Saved episodes share `ui/m1plus_podcasts.bin`. Discover and the search level are there while **Podcast Discover** is on in Settings (the default; `pcsearch_setting`); the Apple storefront they ask is the Podcast Region (a Settings picker, Automatic by default).
The iPod interface also exposes Podcasts.

## Pages and controls

Shows contains Continue Listening, a show grid and Discover/Downloads/Subscriptions/Saved rows, in that order (Discover, tile `pod_ic_discovertile` (Lucide `compass`) with Apple Podcasts in grey, there while Podcast Discover is on (otherwise the Library rows close up: Downloads first); it opens the Discover level; text ends at x 278, the shared list chevron `m1_make_chevron` at x 288, hairline to 310; the episode page's show row likewise).
The Shows, Discover, Downloads, Subscriptions and Saved levels open on the large title (`pg_big`, x `SG_TITLE_X` 12, `SG_TITLE_W` wide, 32 px, cut with an ellipsis); the navbar's small title (the same words, `label_title`) shows once the offset reaches `SG_COLLAPSE` (`m1_title_gone`, `pg_collapse`), as on every large-title page ([navbar](navbar.md) "Small titles"). Its width runs from x 58 to the leftmost visible button (`pg_nav`): the globe (Shows level, while Podcast Discover is on), the Discover level's magnifier or the "...", else Now Playing. The refresh line, section headers and rows keep their own x (14-16).
Shows sort by newest remote or local episode date. The show page has artwork, metadata,
Latest Episode and all known episodes in the show's Episode Order (newest first unless set to Oldest First). The Latest Episode pill is always the newest episode: the first row, the last under Oldest First. A body tap opens episode details;
the pill plays, downloads, pauses, resumes or retries according to state.

Episode details include the long description and the same playback/download actions. Their show row (cover, name, the list chevron) goes back to the show page the episode is on top of: a subscribed show's episode returns to that show's page (it is Back when the page was opened from that show; from Downloads or Subscriptions the show's page opens and Back goes on to that list), a search or Discover preview's episode returns to the preview.
Show and episode sheets provide refresh, unsubscribe, played marks and download removal. The show's sheet rows, in order: Playback Speed (grey value, a tap cycles), **Episode Order** (grey value Newest First / Oldest First, a tap switches to the other, saved at once, then the loaded rows are turned round in place (Oldest First is the exact reverse over the same newest 300, so nothing can fail after the save and the value, the list, the queue and Latest Episode always agree), the sheet stays; a failed save is the toast `Storage unavailable` and no change), **Filter** (grey value All / Unplayed / Downloaded, a tap goes to the next; see "Filter"), Refresh Feed, Select Episodes, Mark All as Played, Unsubscribe (up to seven rows, 350 px, glass `pc_sheet7` for seven on the 450 px window; the rows `order` and `filter` are the last in the asset's fixed rows, glyphs `pod_ic_order` (Lucide arrow-down-wide-narrow) and `pod_ic_filter` (Lucide list-filter), the Filter's value label `pg_sh_filter_vl`; the Filter row is there while the show has an episode or a Filter is on). The Shows level's "..." is there only while the card has something to import (its one row is Import from Card).
Selection supports bulk deletion; the currently playing file is retained.
Deleting an episode clears its saved resume/played state. Unsubscribing preserves local files.

The search level is reached from the Shows level's globe (`btn_globe`, `pg_on_globe`) or from the Discover level's magnifier (`btn_search`, the navbar's left cap beside Now Playing): its navbar title is Apple Podcasts in the empty and the results states, as the keyboard page's; Back (and the keyboard's Back with nothing typed) returns to where it was entered, Shows or Discover (`from_disc`). The Shows level's navbar is `[Globe | ... | Now Playing]`, `[Globe | Now Playing]` or `[... | Now Playing]` (pieces 46 px apart right-aligned to Now Playing; the globe is shown only while Podcast Discover is on, the "..." only when there is something to import, and then is the middle piece `pod_nav_moremid`).
Search accepts directory terms, feed URLs and Apple Podcasts links. Results open a preview (rows of the shared list painter: the hairline from the text to x 310 and the list chevron at x 288, on a result that has a feed only: a dimmed Not available row opens nothing, so it has no chevron and its text runs to x 308 (`grid_tile_t.nochev`));
Subscribe creates a show folder and its metadata. Search previews do not play remote episodes.
Subscriptions supports card import/export, including OPML. The import also accepts
`Podcasts/subscriptions.txt`: one HTTP(S) feed URL per line, with `#` comments.

Saved episodes use stock `myfav` records. The Now Playing favorite control becomes a
bookmark for podcast paths. Its More sheet can return to the playing show's Podcasts page.
There is no separate Saved database.

## Discover

The Discover level (`L_DISC`, `pg_load_disc` and the `pg_disc_*` functions of `patch/podcasts.c`) is Apple's top 25 charts for the Podcast Region (`rss.marketingtools.apple.com/api/v2/<cc>/podcasts/top/25/podcasts.json` and `podcast-episodes.json`). Content from the list top, geometry `patch/offsets.inc` `DC_*`, model `m1_show.discover_layout`:
the large title Discover, the grey line under it (15 px `label_ps_meta`, the Downloads storage line's place: "Top 25 Shows in United States" / "Top 25 Episodes in ...", following the control), the **Shows | Episodes** segmented control (below), then the ranked rows from y 128: the list painter (`grid_list_paint`) shifted 26 px right for the rank (18 px grey `label_row_sub`, right aligned to x 28), so the cover is at x 36, the text from x 100 to 278 (the title, and the grey line: a show's author, an episode's show), the list chevron at x 288, the hairline from the text to 310; thumbnails arrive as for search results (placeholder first). The navbar is Back, the magnifier (`btn_search`, the Radio page's piece, hidden except here) and Now Playing as the capsule's right cap; the small title Discover shows from `SG_COLLAPSE` as on the other levels.

The **segmented control** is one shared painter, `m1_segmented` (`patch/common.c`, with `m1_capsule`; any number of segments): a fully rounded track `SEG_TRACK` (#1C1C1E) 296 x 36 at x 12 (under the large title, as the grey line above it), the selected segment a fully rounded thumb `SEG_THUMB` (#D1D1D6) floating `SEG_PAD` 3 px inside the track on every side with a dark label (`label_ps_latest`), the other labels white (`label_ps_latestw`), a `SEG_SEP` hairline half the track high between two segments that are both unselected (none beside the thumb; with two segments there is none), labels centred in their segments. Neutral: no accent colour. The capsule is painted a row at a time (the chord of the circle, one pixel of partial cover at each end), cut to the view's rows. The font has one weight, so the selected label differs by ink only (no bolder face). No soft shadow around the thumb. A tap on a half (touch 6 px taller than the control) selects that chart.

The refresh dialog's progress fill (`pod_pd_fill`, `#EBEBEC`, role `ROLE_FILL`) takes the accent like Now Playing's; its track stays neutral. The sheets' pressed rows (`#FFFFFD10`, role `ROLE_SHEET_PRESS`) become the accent at 22 % alpha under an accent.

Each chart is fetched on its first view (the tick asks: `pg_disc_sync`; the downloads that run pause first, a running job is cancelled, a refresh is waited for) and its answer kept in memory for the session (`pn.cres`; no card cache): entering Discover again, the other chart and Back from a show page find it held and fetch nothing; the rows' artwork that was not tried (a job was cancelled) is fetched when the chart is in view again. A chart held for another region (changed in Settings meanwhile) is asked again. The worker (`patch/pcnet.c` "Charts", `PN_KIND_CHART`, one worker like search and preview, never touching widgets) makes up to three requests (20 s time-out each, one second apart) for a network or server error or an answer that is not a chart; a **404 or an answer with no rows for a region other than the United States asks the United States chart silently** and the line under the title names the storefront actually shown (`pn_chart_country`). Statuses are the page's words: Loading..., No Wi-Fi, Set the date first, Certificates missing, Storage unavailable, Can't connect, Certificate problem, Server error, Feed not found, No results (the status text is painted in the content under the control, at content y `DC_TOP` + 8, in the dim 20 px grey wrapped to the margins, by `pg_paint_hint` from `pg.htext`, the already translated words; so it scrolls with the title and the control, the content is `DC_TOP` + `PG_HINT_H` and `label_status` is not used; the Apple Podcasts search level does the same under its field at `PQ_TOP`); a failed chart is not asked again by the ticks, a tap on its half or entering the level again asks.

A tap on a row opens the show's preview as a search result does: the iTunes lookup of its Apple id in the store the chart is of (`pn_preview_chart`, `&country=`; a show row's `id`, an episode row's show id parsed from `/id<digits>` of its url: ids pass 32 bits, so they are digit strings), then the feed it names (`pg_open_preview`); the row's grey line reads Loading... meanwhile. A show whose lookup has no feed (PN_NOFEED) is remembered for the session (`pg.dna`, by the id's hash): its row says Not available, is dimmed and has no chevron, as a search result with no feed, and takes no tap, with no toast; any other failure is the toast "Can't subscribe: why" and the row as it was. Back from the preview, from Subscribe's page or from a show that is subscribed already returns to the same chart at its offset (`pg.pv_disc`); Back from the search level returns to Discover too (`pg.from_disc`), from Discover to the Shows level. Each chart keeps its own scroll offset.

An episode row also opens that episode's page on top of the show's preview, once the feed is held. After the feed, the worker makes the store's episode lookup of the show (`pn_pmatch`: `https://itunes.apple.com/lookup?id=<show>&entity=podcastEpisode&limit=20&country=<cc>`, in the chart's store; the row's own id is `pj_chart_t.eid`, the record's `trackId`, parsed by `pj_episodes`), and matches the record to a kept feed item (`pf_match`, `pn_preview_match`): the first item whose enclosure is the record's `episodeUrl`; else the first whose pubDate is in the minute of its `releaseDate` (`pf_iso`); else the first whose title is the same once a leading "586. " is dropped and case and runs of spaces are ignored. The record's `episodeGuid` is not the feed's guid and is not used. `pg_open_preview` opens the match with `pg_det_open`, so Back returns to the show's preview and then to Discover. No match, a failed lookup or an answer without the episode leave the show's preview alone; a Cancel during the lookup cancels the preview (the worker checks it after). Only the 20 kept items can match. Show rows make no lookup. Checked on 2026-11-06 with the 25 rows of the GB Top Episodes: all 25 match by enclosure (the store's `episodeUrl` and the feed's enclosure are the same pdst.fm address), and the date and title rules pick the same item. Fixtures: `test/data/discover/episodes-gb-top3.json`, `lookup-episodes-1611374685.json`, `feed-rest-is-politics-5items.xml`.

The preview's picture is the feed's channel image shrunk to `PN_PREVIEW_COVER`; when that cannot be fetched, decoded or shrunk (some feeds, e.g. The Rest Is Politics, serve progressive JPEGs of 2.25 to 9 MP, which `PC_COVER_MAX_PX` refuses), the store's `artworkUrl600` (a baseline 600 x 600 JPEG of about 100 KB; `pj_result_t.art6`, parsed by `pj_results`, "" when absent or longer than `PJ_ART`) is used through the same shrink path (`pn_preview_picture`). The URL comes with a search result (`pg.sp_art`, passed to `pn_preview`) or from the lookup an Apple id (link or chart row) makes in `pn_pmain`; a typed feed address, an OPML import and Deezer results have none and keep the old behaviour (no picture). Subscribe moves the preview's picture to `cover.jpg`, so the fallback is the show's first cover; `pn_cover` does nothing when the folder has a cover, so a later refresh whose image fails (or succeeds) neither deletes nor replaces it. Tests: `pcjson` (the field), `pcsearch/fallback_tests`.

## Region

`patch/pcregion.c`, model `tools/pcregion.py` (the table is generated into `stock.h` as `PCREGION_*`): 34 storefronts by English name (names are English in every language: no localised country-name table exists here or in the stock tables), saved as two capital letters and a line feed in `/mnt/data/m1plus/podcast-region` (anything else, a missing file included, is Automatic) by the Settings picker ([settings](settings.md)). `pcregion_code()` is the storefront in use: the saved one, else Automatic's: the UI language's country (`ja` JP, `ko` KR, zh_CN CN, zh_HK HK, zh_TW TW, `ge` DE, `fr` FR, `it` IT, `po` PL, `th` TH, `ru` RU, `uk` UA; the tokens are the locale's language and country, `locale_info`), for English and Spanish the Settings time zone's place by its index (London GB, Adelaide / Sydney / Brisbane / Eucla / Lord Howe AU, Auckland / Chatham NZ, Kolkata IN, the US zones US, Mexico City MX, Halifax / St. John's CA, Buenos Aires AR, Amsterdam NL, Bangkok TH, Tokyo JP) unless it is the stock default (22, Shanghai, which names nothing), else the United States. It drives the directory search (`country=<CODE>`) and the chart address (`<cc>` in lower case); the lookup of a typed Apple link is unchanged (no country), that of a chart row is made in the store the chart is of. Nothing runs at paint: the search and a chart ask when they start. Tests: `test/pod/pcregion.py` (every language against every zone against the model), `test/pod/menu.py` `region_row_tests`.

## Files and model

Shows live under `/mnt/mmc/Podcasts/<Show>/`. Root matching is case-insensitive.
Supported file extensions are mp3, m4a, m4b, aac, ogg, opus, flac, wav and wma.
A show can supply `cover.jpg/png/jpeg` or `folder.*`.

| File | Contract |
|---|---|
| `.show` | UTF-8 `M1PLUS-SHOW 1`; key=value lines for title, feed, image, checked, modified, author, category and desc |
| `.episodes` | UTF-8 `M1PLUS-EPISODES 1`; tab-separated key=value fields: g guid, p epoch date, d duration seconds, l bytes, f filename, t title, u enclosure URL, x short description |
| `.archive` | The whole feed, written by Show All Episodes: the `.episodes` format (`M1PLUS-EPISODES 1`, the same fields), the feed's order (newest first), at most 2000 lines and 1.5 MiB (`PC_ARCH_MAX`, `PC_ARCH_BYTES`); see "All episodes" |
| `.notes` | Long descriptions keyed by episode identity; format/read/write implementation in `patch/pcnotes.c` |
| `<filename>.part` | Incomplete download; retained for resume |
| `.m1plus/podcasts/resume` | PCR1 ring: count plus 16-byte hash/position/length/flags slots, most recent first |
| `.m1plus/podcasts/speed` | PCS1: count plus show-hash/mode pairs |
| `.m1plus/podcasts/order` | PCO1: count plus show-hash/value pairs (0 newest first, 1 oldest first); a missing file, entry or bad value is newest first. The key is the show folder's hash, so renaming a folder resets its order. Same 64 slots and eviction as speed (`pm_tab_*`, shared with it) |

Metadata permits LF or CRLF, ignores unknown fields and strips tabs/newlines from values.
The model reads at most 64 KB of `.episodes`, keeping the newest 300 entries. `pc_load_show` returns the episodes already in the show's order (`pc_order_get`; pcmodel.c `pm_ep_cmp`), so the Show page, the iPod episode level, the Downloads scan, Continue Listening and the queue (`pg_episode_queue`: from the tapped episode down the rows) agree; the cap of 300 keeps the newest 300 under either order (Oldest First lists those, oldest first), so the order never changes which episodes are listed. The sort's index lives in the same allocation as the merged entries, so a list is either in the show's order or not returned at all (no memory: no episodes, as before); there is no unsorted fallback.
Titles fit 95 bytes; local filenames must fit 127. Show feed/image URLs use `PC_URL` 320.
Short descriptions contain at most 200 UTF-8 bytes; episode notes at most 4096.

`pm_merge` combines feed entries and files into local, partial or remote episodes.
Without metadata, title comes from the filename and date from mtime.
Sort (newest first) is date descending, filename descending (digit runs by value, case ignored: `cc_key_cmp`, so Ep 10 is later than Ep 2), then entry order; Oldest First is the exact reverse. A show with no metadata entry (only copied files; the dates are copy order) sorts by that natural file name alone: descending for Newest First, ascending for Oldest First. A feed show keeps its publication-date sort.
Refresh preserves old entries whose completed or partial file remains on the card.

Limits: 40 shows, 300 episodes per show (2000 with an archive), 400 examined files (2400 with an archive, `PM_ARCH_FILES`), 4096 resume slots (`PC_RING_SLOTS`, 64 KB: two lists of the longest show; a file of the 512 slots of before is read as it is) and
64 speed records and 64 order records. State writes require `m1_card_mounted` and use temporary files,
fsync and rename. An unmounted card directory must never receive persistent writes.

## Search inside a show

A magnifier (`btn_search`, the Discover level's piece, moved by `pg_nav`) in the Show page's navbar opens a search over that show's episodes: `[Search | ... | Now Playing]`, the three 46 px apart right-aligned to Now Playing (the Shows level's `[Globe | ... | Now Playing]`; the "..." is then the middle piece, the small title ends at the magnifier). It shows on a subscribed show and a show of copied files (with at least one episode), not in a search / Discover preview, on the episode page or in select mode. It is independent of Podcast Discover. Purely local: no network.

- **Page**: `m1plus_pcfind` (`patch/pcfind.c`, a window of its own over the Show page, as the library search is over the Songs page): the Search page's field (placeholder "Search Episodes") with the round X (`pf_close`), our keyboard embedded (`keyboard_attach`) and one content view that paints the rows. Rows are as the Search page's lists (60 px, hairline from x 16 to 310, the pressed fill): the title (21 px, one line cut with an ellipsis, the dim grey of the Show cell's played title when the episode is played) and a grey line (the date as the Show cell writes it, then "· Downloaded" for a file on the card). It is the compact row, not the Show cell: the cell is 140 px tall with a description and a pill row and would leave two rows above the keyboard. Empty field: no rows and no recent searches; no match: the dim 20 px "No results" (`pf_status`). Dragging the list or the action key hides the keyboard, a tap on the field shows it; the X and the hardware Back close the page and the Show page is under it as it was.
- **Matching** (`search_titles_*`, `patch/search.c`, the library search's own folding, terms and engine; `docs/modules/search.md`): titles only, never the descriptions; the field's text is folded (case, Latin diacritics, kana, width) and split at spaces; every term must be in the title. A term of only digits is a **whole number**: it matches a run of digits bounded by characters that are not digits, with leading zeros ignored on both sides, so `37` finds "Ep 37", "#37", "EP037" and "第37集" and not "137", "2037" or "370". A Chinese title also matches by the initials of its characters' readings (`zjl` finds 周杰伦, every reading of a polyphone counts), through the same dictionary engine. The rows are every match in the order of `pg.eps`, i.e. the show's order (`pc_order_get`), 2000 at most. The title is matched anew on every change of the field's text with no debounce (2000 titles are a few million instructions; no incremental filter, no timer).
- **Memory**: one 2000 entry array of 16 bit indices (4 KB), 16 text tiles, the matcher's `se` state of `patch/search.c` (shared with the library search, so the page does not open while a Search page exists). The 1 MB pinyin engine and the 21 KB reading table are held **only when some title has a character of U+4E00 .. U+9FFF** (checked once at open, `search_titles_hanzi`), until the page closes; a show with Latin titles never opens them.
- **Tap, Back**: a tap on a result keeps the text and the scroll (`pf_keep`, outlives the window), opens that episode's page on the Show page below (`pg_find_pick` -> `pg_det_open` with `pg.from_find`) and closes the search page. Back from the episode page (`pg_on_back`) opens the search again (`pcfind_reopen`) with the text and the scroll, the keyboard down (a tap on the field raises it). The episode page's show row, leaving the show and any other way out of the page forget it. Playing from the episode page queues as the Show page does: `pg_episode_queue` over `pg.eps` from that episode down in the show's order (not the following results). The list the page reads is the Show page's (`pg_find_count`, `pg_find_ep`, `pg_find_played`; the Show page's tick is stopped while the search is in front, so it reloads at its to-foreground event).
- **Tests**: `test/pod/pcfind.py` (`more_tests` the Search All Episodes row: presence, tap, count, end, failure, paused download, leaving, episode page, Chinese archive, Filter; `nav_tests` the button, `match_tests` the matcher incl. the digit negatives and pinyin, `flow_tests` rows, tap, Back, scroll kept, `queue_tests`, `asset_tests`), `pcsearchui` (the Show page's navbar). Strings: `Search Episodes` (13 languages, machine translated, unreviewed).
- **Search All Episodes** (`pg_find_more`, `pg_find_more_tap`, `pg_find_sync` in `patch/podcasts.c`, `pf_*` in `patch/pcfind.c`): for a subscribed show with no `.archive` (exactly the Show page's row condition, `pg_more_on`) and a field that is not empty, one extra row ends the results, a compact 60 px row in the title style with no chevron and no grey line, painted white and tappable, dim while the job runs. With no match it stands alone at the top of the list and the dim "No results" stays under it (its own place, y 150). The text comes from the Show page's `pg_more_line` (idle "Search All Episodes"; "Loading…" and "Loading… 340"; after a failure the reason and "Tap to Retry"), so the job, its guards' toasts, the pause of running downloads (`pg.apend`) and the keep-awake are the Show page's own (`pg_arch_tap`). A tap while it loads does nothing; typing and tapping results go on. **Timer**: the page has a 1 s timer (`pf_tick`, alive with the window). The Show page's tick is stopped under this page, so the job's start (a tap that waited for the downloads, `pg_arch_pend`) and end (`pg_arch_poll`) run from the downloads' timer `pg_awake_tick`, which the job arms and which runs in the background; `pf_tick` then calls `pg_find_sync`, which does the Show page's own reload (`pg_reload_eps`: `pg.eps`, the Filter's index array, `has_arch`) when `pn_gen` moved. Archive appeared: the pinyin hold rule is checked again over the new titles (`pf_hold`), the query runs anew, the list starts at the top and the row is gone. Another reload (a download finished): the same query, the scroll kept. Otherwise `pf_tick` only repaints the row when its text changed. A failure is on the row (the toast is the Show page's, only when it is in front); a cancel shows nothing. Leaving the search leaves the job running (the Show page shows its count and result as before); an episode opened from a result and Back: the row shows the state then. The Filter is not read by any of this; the reload keeps it. Not device-tested. Not done: highlighting the match; a title of two lines; not device-tested.
- **Filter**: the search page ignores the Show page's Filter (see "Filter"): `pg_find_*` read `pg.eps` whole, `pg_find_pick` takes an episode index, and its queue is the show's full order (`pg_episode_queue` over `pg.eps`).

## All episodes

A subscription keeps the 20 newest feed items in `.episodes` (the refresh's `PF_KEEP`; entries whose file is on the card stay besides), so older episodes are not listed. **Show All Episodes** (the last row of the Show page, `PS_MORE_H` 56 px under the last cell, `pg_more_on`, part `PH_MORE`) fetches the feed again and writes every item to the show's `.archive`.

- **Row**: shown for a show with a feed address and no `.archive` (`pg.has_arch`, set when the list is made or read again), not in a preview, not for a show of copied files, not while rows are marked (select mode drops it and its height), not for an empty list. Text white "Show All Episodes"; while the job runs for this show, "Loading…" and the number of items written so far ("Loading… 340": `pn_arch_count`, the attempt's own count, read by the page's tick, so it moves about once a second; `pg_more_line`) in the dim grey, and plain "Loading…" while it waits for the downloads to pause or has no item yet (a tap then does nothing). No percentage: a gzip feed has no usable length. A failure is a toast with the page's words (No Wi-Fi, Can't connect, Feed not found, Not a podcast feed, Storage unavailable...) when that show is on screen, and stays on the row: "Can't connect · Tap to Retry" (the same words, `pg_status_word`, and the hint) in white; a tap starts the job again. The failure is remembered for the session by the job (`pn_arch_failed(hash)`: one show, the last failure; a new start of that show, a success and a cancel clear it), so leaving the show or the page and coming back still shows it. A cancel shows nothing. After success the next reload (the job's end moves `pn_gen`) has no row and the long list. Downloads running at the tap are paused first (`pg.apend`, the page's tick starts the job when they have) and go on when the job ends.
- **Job** (`pn_arch_*`, `PN_KIND_ARCH`, `patch/pcnet.c` "All episodes"): one worker job of the same slot as the others (`pn_job_busy`, not `pn_busy`: no refresh dialog); state `PN_AR_*` of the show `pn_arch_hash`, reset by the page's tick or, while the page is in the background, the downloads' timer (`pg_arch_poll`, which also toasts and restarts the paused downloads; the start of a tap that waited for the downloads, `pg_arch_pend`, runs from both, so the search inside the show can use the row too). **Cancel**: the worker's own `pn.cancel` (the transfer callback aborts, `PN_CANCELLED`; no `.archive`, no temp file, no toast, nothing remembered); every action that cancels a running job by `pn_job_busy` (Discover's pump, the search and preview pumps, clearing or leaving the search) cancels this one the same way. Refresh and Refresh All are refused with no word while it runs (`pn_refresh` returns `PN_BUSY`, as for a search job) and Unsubscribe does nothing (`pg_unsub`), as before. No cancel control: a tap on the row while it loads does nothing, and the job continues when the Show page is left for another Podcasts level. **Awake**: `pg_awake_arm` arms the downloads' timer for the job (`reset_poweroptions_timer(1, 1, 0)`, so the screen may sleep but the standby and the Wi-Fi do not). **Page closed**: `pg_on_destroy` cancels the job with the other jobs; the downloads it paused would wait for the next opening, so a page-less timer (`pg_resume_tick`: UI thread, no widget, calls only `pn_*`) starts them once the worker is free and ends. (A refresh or search job cancelled by closing the page still leaves paused downloads waiting for the next opening; not changed.) The feed is requested up to three times (`PN_ARCH_TRIES`, one second apart as the charts; only a network error, a time-out, a stall, HTTP 5xx, 408 and 429 are asked again; 404, 410, other 4xx, a page that is not a feed, a certificate, storage, memory and a cancel are final), each attempt with a fresh `.archive.tmp`, parser and count (300 s limit and 60 s without a byte, `PN_DL_STALL`, per attempt; a 32 MiB decoded cap; certificates verified as every request) and parsed by the same streaming parser in **sink mode** (`pf_set_sink`: every enclosed item goes to the sink at its end tag and none is kept; the 20-item window of a refresh is untouched). The sink writes one line per item (`pf_item_line`, the refresh's own line writer) into `.archive.tmp`, 16 KB at a time; the file replaces `.archive` through `m1_commit` (fsync, rename; a failure or a card that is gone removes the temp file). An item whose guid `.episodes` has takes that entry's file name and description (so a downloaded episode keeps its file); the others are named as a refresh names them (`pf_item_file`; a clash with an earlier line of the file, by `pc_hash` of the name, is numbered "(2)"). Caps: 2000 items and 1.5 MiB, whichever comes first (the feed's newest, as feeds list them); the transfer is stopped there and that is a success. A feed with fewer items gives fewer; a feed with none, a page that is not a feed, a 404 and the rest fail with no `.archive`. Long descriptions (`.notes`) are not written for archive items: their episode page shows the short description (`x=`).
- **Model** (`pc_load_show`, `pm_add_archive`): with an `.archive` the list is `.episodes` (up to 300) plus the archive's entries (up to 2000 lines) minus the archive entries an earlier `.episodes` entry has (same guid hash; without a guid, same file name), merged with the files on the card (`pm_merge`; the folder scan takes up to `PM_ARCH_FILES`, 2400, files for such a show, so every downloaded episode of the archive is PC_LOCAL, and `pm_find` compares a hash of the name before the name), sorted as before (`pm_ep_cmp`, `pc_order_get`), and cut to the newest `PC_ALL_MAX` (2000, either order). Entries in the archive match files by `f=`, so played marks (ring keys of the path), notes lookups, downloads and removals work as for any row. `pc_has_archive` / `pc_eps_cap`: callers allocate `pc_eps_cap(show)` entries (456 bytes each: 912 KB at 2000, transient 1.2 MB for the merge) and pass it as `max`; the Show page (`pg_eps_of`), the iPod episode level, Continue Listening and Unsubscribe do. Downloads of an archive-only episode find the url in `.archive` (`pn_find_url`: `.episodes` first).
- **Surfaces**: the Show page, its queue (`pg_episode_queue`, over `pg.eps`), select mode (the mark bitsets are `PG_PICK_MAX` bits, 2000), Mark All as Played, Delete, the iPod episode level (files only) and Continue Listening see the whole list. The Downloads page scans files, not lists (`PG_DLD_MAX` 300 downloaded rows, as before); the Shows level's counts and the show's `newest` date read `.episodes` only. Episode Order's flip reverses the list in place, which is still exactly the reload (the cut is the newest 2000 under either order).
- **Refresh and Unsubscribe**: a refresh never reads or writes `.archive`; new episodes arrive through `.episodes` and reach the list through the union (an episode that falls out of `.episodes`'s window stays in the archive). Unsubscribe with no file left removes `.archive` with the rest (`pn_unsubscribe_show`, `pg_unsub`); with files left it stays with `.episodes`.
- **Tests**: `test/pod/pcarchive.py` (`job_tests` the job, names, caps and failures; `model_tests` the union, dedupe, order, caps; `refresh_tests`; `download_tests`; `row_tests` the row, tap, Loading…, reload; `retry_tests` attempts, waits, final failures, stall options, the count, cancel; `page_tests` the count on the row, the failure that stays and its retry, leaving and returning, another job cancelling, awake, background, page closed; `select_tests` a 1008-row list), `pcshow` / `pcsel` / `pcdetail` / `pcsearchui` content heights with the row.
- **Open**: nothing runs automatically for a show set to Oldest First with no archive (the row is at the end of the list, so Oldest First reaches it only after scrolling the newest 20 to the end); no cancel control for the user (leaving the page, or Discover and search, cancel it); a feed of more than 2000 items keeps the newest 2000, so the very first episodes of a longer show are not reached; not device-tested (parser speed over a 10 MB feed, memory with a 2000-row list on the device).

Handover (the Filter below is built on it): the merged list is built in `pc_load_show` (`patch/pcmodel.c`) and held in `pg.eps` / `pg.neps` (`pg_eps_of`, `pg_reload_eps`); rows are indices into it, so a filter is a second index array over `pg.eps` (title in `.title`, short description in `.desc`, state in `.state`, played via `pg_ep_state`) that `pg_count`, `pg_hit`, `pg_paint_eps`, `pg_cell` and the queue builder must go through (they all use the row index directly today, with cells of the fixed `PS_CELL_H`); the select mode bitsets index `pg.eps` and are sized for `PC_ALL_MAX`. The long notes (`.notes`) exist for the newest 20 only. `.archive` is plain `.episodes` text, readable with `pc_parse_eps` (`PC_ARCH_BYTES` cap).

## Filter

A long show hides what it need not show. **Filter** is the show's "..." sheet row after Episode Order (`SR_FILTER`, `pg_sh_filter`, grey value `pg_sh_filter_vl`, shown by `pg_sheet_value` as Episode Order's value is: neutral grey, the label keeps its whole text) with the values **All**, **Unplayed**, **Downloaded**; a tap goes to the next (`pg_filter_cycle`) and the sheet stays, as for Episode Order. The sheet is seven rows at most (350 px of the 450 px window, `pc_sheet7`).

- **Rows**: an index array over `pg.eps` (`pg.vis`, `pg.nvis`, `pg.filt`; `pg_vis_make`). `pg.vis` is NULL for All, so every row is its episode; otherwise `pg_ix(row)` is the episode's place in `pg.eps` and `pg_nrows()` the count. Everything that takes a row maps through them: `pg_count`, the cell layouts (`pg_cell`), paint (`pg_paint_eps`), hit testing (`pg_hit`), the select marks and their bitsets (rows, `pg_pickable`), Select All, Delete, Mark All as Played and its sheet row (`pg_any_unplayed`), the queue (`pg_play`). What takes an episode (the episode page `pg.det`, `pg_cell_tap`'s map of a row to `ep`, the sheet of a cell, the Latest Episode pill, Unsubscribe, the search inside the show) uses `pg.eps` and episode indices directly. The array is 2 bytes an episode, allocated only while a Filter is on (no memory: the Filter is All and the toast says so).
- **Predicates**: Unplayed = `pg_ep_state != PC_DONE` (the cells' played check: a partly played one is unplayed, an episode with no file name too); Downloaded = `state == PC_LOCAL` (the cells' disc). The show's order is kept (both orders); Episode Order's flip and every reload make the array again.
- **State**: page state, not saved (no file on the card or `/mnt/data`). It is reset by leaving the Show level (`pg_eps_free`) and by opening another show or a preview (`pg_open_show_with`); the same show opened again from itself (after a refresh) and the episode page, the search page and Now Playing keep it. A reload (`pg_reload_eps`: a download finished, a file was removed) keeps it and makes the rows again, so a row leaves or joins then. **A mark made while Unplayed shows does not move the row**: it stays, grey, until the list is made again (a filter change, a reload).
- **Queue**: playing from the filtered list queues the rows shown (the local ones among them, in the show's order, the tapped one the current: Previous goes back up the shown rows), `pg_queue_of` over `pg.vis`. An episode opened from the search inside the show (`pg.from_find`) is played with the whole list, whether the Filter shows it or not (`pg_play`). **Mark All as Played** marks the rows shown from the last to the first with `pc_mark_hold` and writes the ring once (`pc_flush`); the ring's 4096 slots hold a 2000 episode list twice, so no mark of the list is let go. The Latest Episode pill's episode, if the Filter hides it, plays with the whole list. The search inside the show and `pg_episode_queue` (also the iPod level's) keep the show's full order.
- **Empty**: a Filter that leaves no row shows the dim hint under the header ("No unplayed episodes" / "No downloaded episodes", `pg_hint`), the header and the navbar unchanged (the "..." is there to switch back). The **Show All Episodes** row stays under any Filter for a subscription without an archive; with no row it sits under the hint (`pg_more_y`).
- **Ignore it**: the Latest Episode pill, Continue Listening, the iPod episode level, Downloads, the Shows level's counts and the search inside the show.
- **Tests**: `test/pod/pcfilter.py` (`sheet_tests`, `rows_tests`, `state_tests`, `index_tests` hit testing, episode page, sheet, queue and Latest pill by row, `select_tests` marks, Select All, Delete, Mark All, `empty_tests`, `find_tests`), `pcshow` sheet tests (seven rows). Strings: `Filter`, `Unplayed`, `No unplayed episodes` (13 languages, machine translated, unreviewed). Not device-tested.

## The Downloads page

The Downloads level (`L_DLS`) has the large title Downloads, the storage line (`PDL_LINE_Y`, "7 episodes · 217 MB · 18 GB free") and the rows of two sections, In Progress (what the worker holds, then the failed and the paused) and Downloaded (the files on the card, the newest download first). Geometry `patch/offsets.inc` `PDL_*`, `PP_HEAD_PITCH`, `PP_SEC_GAP`; model `tools/pod_show.py downloads_layout`, the C side `pg_dy`, `pg_dhead`, `pg_dh`, `pg_dhit`.

- **Section headers**: a header ("In Progress", "Downloaded", 20 px white, `pg_paint_head`) is drawn, and takes `PP_HEAD_PITCH` of height, **only when both sections have rows** (`pg_dheads`). With one section alone the large title already names the page, and "Downloaded" right under "Downloads" read as a repeated title, so there is no header: the rows start at `PDL_LINE_PITCH` (80), where the first header would have started, with the storage line above them as before. With both, the layout is In Progress header, its rows, `PP_SEC_GAP`, the Downloaded header and its rows. ## Playback, resume and speed

Episodes use class-1 folder queues with copied song records; playback needs no library scan.
The tag-reader hook supplies show/episode text only for podcast paths.
Library query filtering removes podcast paths from music lists and music Favourites;
Daily Mix, Recently Played and custom Shuffle queues also exclude them.
Folders and stock history tables can still contain episodes.

`pc_note`, called by Now Playing, the mini player and the Podcasts page timer, records
positions only while those pages provide ticks. Positions from 30 seconds are saved;
within 30 seconds of the end or past 95% the episode is marked played.
Writes are limited to every 30 seconds, with immediate flushes on pause, track change,
page actions and backgrounding.

A saved position resumes once playback reaches 1..4 seconds; it is abandoned after 15 seconds
if it cannot be applied. Played episodes restart at zero.
Per-show speeds are 1×, 1.25×, 1.5× and 2×. They change RAM/player state without writing
stock PLAYSPEED configuration; music restores the previous mode. Actual application of
speed changes can depend on the stock player's next track open.

## Network and feeds

One worker handles refresh, search/subscription, charts or downloads; it never touches widgets. The Radio directory fetch (`rd_fetch`, [radio](radio.md)) is refused while one of these runs; the reverse is not checked.
The UI reads generation/status records. Downloads pause for other network jobs and resume
afterward. The queue holds 32 entries in RAM; reboot leaves partial files paused.

Requests use the firmware CA bundle with certificate verification enabled, bounded HTTP(S)
redirects and connection/transfer guards. Missing Wi-Fi, an invalid clock or missing
certificates produce explicit errors. Feed requests have an 8 MiB cap and 120 second timeout.
Conditional requests use the server's Last-Modified time, never the device clock.
A 304 preserves episodes; a missing episodes file forces an unconditional retry.

The streaming RSS parser keeps the 20 newest enclosed items, handles arbitrary chunk splits,
entities and CDATA, and strips HTML from descriptions. Atom is unsupported.
Refresh writes episodes before show metadata and preserves local filenames.
Cover failures do not fail the feed or replace user-supplied artwork.
Large JPEG/PNG art is reduced to 192 px with bounded-memory decoders; malformed images
fail without exiting the app. Display decoding refuses images over 2.1 million pixels.

## Download safety

Downloads request the stored enclosure URL, not an expiring redirect URL.
Data is flushed in 512 KB chunks and renamed only on completion.
A partial file requests Range N-: HTTP 206 appends, 200 restarts, and 416/range errors
restart once. Content-Range offsets are not validated.

Transient failures retry after 10, 20 and 40 seconds. Certificate, storage and terminal
HTTP errors fail immediately; text responses are rejected as non-audio.
Downloads keep 32 MB free, reject bodies over 2 GiB and enforce a 240-byte path limit.
Nonempty partial files survive errors and cancellation; empty ones are removed.
There is no automatic new-episode download or persistent retry queue.

Active transfers use the stock power timer to prevent standby while allowing screen-off.
Visual work stops while dark; status and covers update on the first lit page tick.
Stock standby otherwise stops Wi-Fi and CPU execution.
