# Playback settings

Settings > Playback Settings is one own cards page (`m1plus_playset`, `PLAYSET_PAGE`, `patch/playset.c`) that replaces stock's `playset/playset_page` ("All Playback Settings") and its sub-pages the way [Buttons & Power](keyspower.md) and [Display](display.md) replaced theirs: our own rows, stock's own state words and
`[PLAYSET]` / `[SYSSET]` config saves, setters that repeat stock's click handlers store for store and call for call in the same order (the three loudness pages bind stock's own handlers instead, "Loudness pages"), nothing of ours saved, no row opening a stock page, values read again when the page opens and when its window comes back to the front.
Phase 1 (the analysis below, "The stock list" to "Pull-down Output tile") is the static reading of stock V2.1 `demo`; phases 2a and 2b are the page and the three loudness pages. All addresses are `demo` virtual addresses (disassembly by `tools/disasm.py`, cache `work/cache/demo.dis`).
Not run on a device; the emulator tests run stock's own handlers (`test/pod/playset.py`).

Rules shared by the rows:

- A picker's choice is stock's click when it differs from the state shown (stock's handlers call their set function only then); the chosen value shows a check, and every state is read again on `EVT_WINDOW_TO_FG`, so a change made elsewhere (the pull-down's Gain and Output tiles, stock's own pages) shows when the page is back in front. A setter refuses a value stock does not have (-1) and writes nothing.
- The getters of the mcl words are stock's own functions (tools/pod.py `FUNCTIONS`), called as stock calls them; the words without a getter (`memory_play`, `digital_flag`, `usbvol_mode`) are read directly (tools/pod.py `DATA`, checked against `demo`'s dynsym by the build). A value out of range (config_init clamps every one at load) shows the first choice.
- `save_stop_player` / `save_start_player` are called at stock's addresses, so Internet Radio's hooks over them ([radio](radio.md)) see the DSD change as they see stock's: while a station runs it restarts on the new output.
- Pins: `tools/pod_pins.py PLAYSET_PINS` (the click handler's entry and prologue, every case's reads, stores, saves and setter calls, the five set functions' stores, saves and calls, and the mcl getters and setters by their first words). Nothing of ours is saved; no new hook; nothing is boot-reachable.
- **Gain at Line Out.** The row follows the byte: dimmed and insensitive on open and on return to front, so the pull-down's Output tile (which sets the byte and forces the gain high at the hardware, `mclSetGainMode(1, 0)`) is reflected when it closes. The value shown is the stored word (stock's own `GAIN` is untouched by Line Out).
- **The pull-down's Playback Settings tile opens our page** (`pd_open_settings`, [pulldown](pulldown.md)): restacked when `m1plus_playset_page` is in the stack, else opened as the Settings row opens it; stock's list only if ours will not open. Our page never sets `playsetinto_flag` (stock's page init does; [settings](settings.md) "stock pages and state"), so `pd_reconcile` reads the flag from either window: the tile is disabled over our page and over its pickers and slider pages (each is a window above ours), and live behind the player. See "Reaching stock's list" for where stock's own list can still be opened.
- **Still stock.** The Control Center's Gain and Output tiles and `audiosetting_page` (and so stock's `filter_page`, `maxvol_page` and `balance_page`) still open stock's pages; `playset/playset_page` and its sub-pages stay in the asset tree. A later phase decides what to do with them. The EQ row of stock's list still opens our Equalizer ([peq](peq.md)) (`EQ_ROW`).
- **Not on the page, ever:** EQ (our own row on the Settings root, [peq](peq.md)), Enlarged album art (`pset_covermode`, [bigcover](bigcover.md): byte `0xa05aa5`, `[SYSSET] COVERMODE`, already our Idle Display) and Single Dual DAC (`pset_dac`, stock never lists it, "Single Dual DAC" below).

### Reaching stock's list

Stock's own All Playback Settings (`playset/playset_page`) is still in the build for a fallback. Read from `demo` and the built `demo` (the stock ELF against the package built by `make test`; no device): (1) the Home icon dispatcher `0x533b80` (jump table `0x751930`, 18 entries by icon id; entry 16 = `0x533d28`) loads the string `"playset/playset_page"` (`0x749a64`, `0x533d30` in the delay slot) and branches to the shared `navigator_to` call `jalr` at `0x533c78`. Our hook 1 over the dispatcher's first three words (`m1plus_home_click`) handles only the M1+ Music icon (id 99) and the recovery tap on id 1, and passes every other id to stock (resume `0x533b8c`); the case body, the shared call and the jump table are byte-identical to stock's in the built `demo`, so id 16 reaches stock's list. `navigator_to` itself is not hooked, and hook 22 patches only `on_wm_tsmove_fun`'s two sites (`PULLDOWN_OPEN_SITES`). (2) Id 16 is the stock Home grid's `playset` icon (English label "Play Settings", `tools/mod_icons.py`), in the default Home list (`main_allmenu` ids 0..17); Settings > Developer > Open Shanling Home shows that grid ([home guard](home-guard.md)), so the icon is the one to tap. Not checked: that the icon is shown on the user's card (stock's Home customisation can hide it, config `[MAIN] HOMEMENU`) and the screen itself on a device. Opening it that way does not set our flags beyond stock's own init (`playsetinto_flag` = 1), so the pull-down's tile is disabled over stock's list and the tile, used from there, opens ours. (3) `audiosetting_page` (stock's five-row Gain / Filter / Max Volume / DAC Charging / Balance list) is opened by `navigator_to_with_context` from two click handlers, none patched in the built `demo`: `0x521d9c`, bound by name to `btn_playerset` (`0x522618`; the widget is in `airplay_page.bin` and `bluetoothrecv_page.bin`, the AirPlay and Bluetooth-receiver pages), and `on_usbmodeset_onclick` `0x545534`, bound to `btn_dacset` (`0x545730`) of `usbmode_page` (the USB mode page); plus the registry entry `0x4d0288` (a name table, not a caller) and `on_bluetoothback_onclick` `0x529e6c` (its own `btn_playerset` use, not traced further). That the buttons are visible on those pages and how the pages are reached on a device is not verified.

### Loudness pages

Max Volume, Default Volume and Channel Balance open slider pages (`m1plus_psmaxvol`, `m1plus_psbootvol`, `m1plus_psbal`, `tools/pod_pages.py PSMAXVOL_PAGE ..`, built by `tools/pod_ui.py cards_volcard`). A page is a value card (one row high, the card piece `single`) holding stock's label by stock's name (`label_vol`, `label_balance`, white, centred) over a control card holding stock's `btn_dec` and `btn_add` (46 px wide buttons: `-` and `+`, on Channel Balance `L` and `R`, a step toward the left or the right; no fill and no border in any state, `border_width` 0 and a transparent `border_color`, because the theme's default button style draws a square border otherwise; the text 24 px over a faint round disc, the insensitive views `pod_vsdisc_dec` and `pod_vsdisc_add`, 36 px, 8 % white, drawn before the buttons, which stay the touch targets) either side of stock's slider (`vol_slider` 0 .. 100, `slider_balance` 0 .. 20) in the Display page's slider look; the slider is 184 px wide, its ends 13 px clear of the discs. Default Volume has the Volume Memory switch row (glyph `memory-stick`) above the two cards.

**Stock's own handlers run.** As the Display page does for brightness ([display](display.md)), the page's window binds stock's handlers to the widgets by name with the window as their context (`patch/playset.c ps_vol_opened`; `PLAYSET_PINS`): the slider's handler on EVT_VALUE_CHANGING and the two buttons' on EVT_CLICK, exactly the events and handlers stock's page inits bind ("Per row"). Nothing of the stores, the clamp of `volume` to the new max, `set_devicevolume` (only while `headset_output != 2`), the saves (`VOLUME` then `MAXVOLUME`; `BALANCE`; `BOOTVOLUME`), `reset_poweroptions_timer(1, 1, 1)` or the refresh is repeated in the payload, so the order, the arguments and the guards cannot differ from stock's. Stock's refresh (`0x49efec` / `0x49d160` mode 1 / `0x49cb8c`: it writes the label as `VOL: %d`, `L%d`, `0` or `R%d` and sets the slider from the word; on Max Volume and Default Volume that label is hidden and our own `pod_vsnum` shows the number alone, below) runs when the page opens, before the handlers are bound (setting the slider is then not a change to save), and each time the window comes back to the front (`EVT_WINDOW_TO_FG`), the same call as stock's handlers make themselves. The one control without stock's code is Volume Memory (`ps_bootmem_toggle`): stock's click (`0x49d328`) needs its switch image and its hidden `bootvol_view` for the redraw, so the payload repeats the stores and the save (the byte xor 1 stored as the save's callee starts, `write_int_config(byte, "PLAYSET", "BOOTVOLFLAG")`) and dims the cards itself.

**The number alone.** Max Volume and Default Volume show "80", not "VOL: 80". The page keeps stock's `label_vol` (visible false, sensitive false) for stock's refresh and handlers to write into, and shows `pod_vsnum` (the same look, centred), which `ps_vol_num` sets from the word (`max_volume` / `boot_volume`, `%d`) on open, on `EVT_WINDOW_TO_FG` and after every slider change and button tap. Our handler (`ps_num_max`, `ps_num_boot`, context the window) is bound to the same three events as stock's, **bound before stock's**: stock's `emitter_on_with_tag` (`0x6f45ac`) puts a new handler at the head of the emitter's list (`new->next = items; items = new`) and `emitter_dispatch` (`0x6f4458`) walks from the head, so the newest runs first and ours, bound first, runs after stock's; stock's six handlers all return 0 (the dispatch goes on; only 0xb stops it), so ours always runs and reads the word as stock stored it (`volnum_tests` runs the handlers newest first and checks the label against the word; `pin_tests` checks that ours is bound before stock's on each widget). Channel Balance keeps stock's own text (`L3`, `0`, `R2`).

**When each control saves** (stock's own, read from the page inits): every control writes at once, nothing on release or on leaving the page. The slider is bound to EVT_VALUE_CHANGING only, so a drag saves on every changing event, which is as often as stock's page does and no more (EVT_VALUE_CHANGED, release, is not bound); a button saves on every tap. Max Volume's slider and its dec button lower the volume at once (`volume = max`, `set_devicevolume(volume)` unless `headset_output == 2`, `VOLUME` saved, then `MAXVOLUME`); its add button and a raised max never raise the volume. Channel Balance calls `set_devicevolume(volume)` after every store (unless `headset_output == 2`); the sliders save and call also from their drag. Default Volume applies nothing live (boot only, "Boot" above).

**Stale values.** Max Volume's page shows only the max (`label_vol` and the slider from `max_volume`); the volume keys open the volume dialog over it and change `volume`, which the page does not show. Every handler reads `volume` (and `headset_output`) when it runs, so a change after the volume keys compares with the volume as it is then (`test/pod/playset.py maxvol_tests`). The refresh on return to the front reads the words again.

**Default Volume's cards under Volume Memory.** Stock hides and disables its slider view while the byte is set (`0x49d2d8`, `0x49d2ec`). Our cards stay in place, dimmed to 60 % opacity and insensitive (`ps_vol_dim`: `pod_vsval` and `pod_vsctl`); a tap on the switch dims or restores them at once (`on_switch` refreshes the page), and the page refresh does it on open and on return.

**The rows' texts** (the main page, `ps_value_text`): Max Volume the number, Default Volume `Memory` while the byte is 1 (the byte decides, as stock's page does) else the number, Channel Balance the text stock's label shows: `L3`, `0` for the centre, `R2` (stock's own forms, no translation needed; `test/pod/playset.py balance_tests` checks all 21 values against stock's refresh).

### Labels

Our own short English keys (stock's translations of these rows are partly wrong: French "avoir ralenti" for ReplayGain, Italian "Modalità di gioco" for Play Mode); all in the 13 languages ([i18n](i18n.md)), measured to fit by `test/pod/i18n.py`. Abbreviated or shortened for the 13 languages: Play Mode (fr Mode, de Modus, es Modo), Resume (de Fortsetzen, es Reanudar, it Riprendi, pl Wznów, ru Возобновить, uk Відновити, th กลับมาเล่น; each differs from Continue Playing's), Folder Skip (de Ordnersprung), and the filter names in fr, de, es, it, pl, ru and uk (Lin. / Мин. style abbreviations, "apodyz.", "dispers."). The click handler reads the row number from the item's name (`atoi(widget name)`), maps it through the same `0x97c7d0` table to the id and jumps through `0x747650 + 4*id` (ids above 16 do nothing). Rows are bound to the handler by `widget_on(row, 0x10c, 0x49ffe8)` (`0x4a0880`).

**Conditions.** Every row is always shown; no row is hidden by output, play state or another setting. The only conditional is Gain: when the Line Out byte `output_way` (`0xa05aa7`, [lineout](lineout.md): set by the pull-down's Output tile, `[SYSSET] OUTPUTWAY`, config_init `0x4e5e98`: values >= 2 become 0) is non-zero, the Gain row's label uses `srlabel_leftgray21_style` instead of `srlabel_leftwhite21_style` (`0x4a0720..0x4a0734`) and its click case returns at once (`0x4a021c..0x4a0224`, nothing stored, no dialog, no toast). Nothing else tests output, play state or another row.

**Window.** The init (`0x4a0c88`) binds `btn_return` (`0x4cd574`) and `btn_backtoplayer` (`0x4cd58c`) through a `widget_foreach` (`0x49fee8`), stores 1 in `playsetinto_flag` (`0xa05a4c`, read by the pull-down, see [settings](settings.md) "stock pages and state" and [pulldown](pulldown.md)) and calls the builder. The back handler (`0x49fec0`) stores 0 in that flag when it is positive and tail-calls `0x4d20dc`. The list is built once, from the init; no refresh on return to the front was found in the page's code (the chevron rows show no value; the Gain image and the switch rows change only through the list's own clicks).

**Entry points of `playset/playset_page`** (`strings-xref`): `on_wm_tsmove_fun` `0x4cd898` (the pull-down's Playback tile, now `pd_open_settings`, payload hook 22), the Home destination dispatcher `0x533d30` (id 16, `HOME_PLAYSET`; no row of ours opens it now), and the page-name registry `0x4d1a24` (`on_wm_timer_rgbled_state`, one name entry per page, with the same shape for every sub-page below).

**A second stock caller of three sub-pages.** `audiosetting_page` (init `0x52934c`; opened from `0x4d0288` registry, `0x521dc4` `gesture_create`, `0x529e6c` `on_bluetoothback_onclick`, `0x54555c` `on_usbmodeset_onclick`; not traced further) is a five-row list (click jump table `0x750fe0`, handler `0x528b40`) whose rows do: case 0 `0x528ba0` the Gain toggle (the same sequence as the playset Gain row, `0x528bd4` `write_int_config(new, "PLAYSET", "GAIN")`, `0x528be8` `mclSetGainMode`, with the same Line Out test `0x528ba0`), case 1 `0x528c8c` `navigator_to("playset/filter_page")` (`0x528c90`), case 2 `0x528ca8` `playset/maxvol_page` (`0x528cb0`), case 3 `0x528cb4` the `DAC_CHARGE` toggle (`toolsSetChargeSwitch`, `[PLAYSET] DAC_CHARGE`, label `usb_chargeswitch` "USB DAC Charging"), case 4 `0x528dc8` `playset/balance_page` (`0x528dc8`). **Stock's `filter_page`, `maxvol_page` and `balance_page` therefore stay reachable after our page replaces the list**; they must stay in the asset tree (or `audiosetting_page`'s three rows must be redirected too). The pages `bootvol_page`, `memplay_page`, `playmode_page`, `replaygain_page`, `systemset/dsdmode_page` and `systemset/usbvolmode_page` are reached only by the playset click handler (xref above) and the registry.

## Machinery shared by the rows

### The mcl state words and calls

The mcl module keeps its own copies in `.bss` (`GOT page 0xa10000` plus a displacement; `fd` is `0xa0abf8`, the word `-0x5408`). The setters below that touch the driver do nothing at all when `fd <= 0` (`blez` at the top), and the config save of the click handler happens anyway.

| Call | Address | Effect (read) |
|---|---|---|
| `mclGetGainMode` / `mclSetGainMode(mode, store)` | `0x5d44cc` / `0x5d5a4c` | word `0xa0abbc`; set: if `fd > 0`, store `mode` in the word when `store != 0`, then `ioctl(fd, 0xc0044d0d, &mode)` |
| `mclGetfilter` / `mclSetFilter(i)` | `0x5d452c` / `0x5d5b64` | word `0xa0abac`; set: if `fd > 0`, `ioctl(fd, 0xc0044d19, &i)` with the word stored in the call's delay slot |
| `mclGetDacNumber` / `mclSetDacNumer(v)` | `0x5d4514` / `0x5d5aac` | word `0xa0abb0`; set: if `fd > 0`, `ioctl(fd, 0xc0044d1d, &v)`, then the word |
| `mclSetLineOut(v)` | `0x5d5e98` | no state word: if `fd > 0`, `ioctl(fd, 0xc0044d06, &v)` (stock's name; the UI row is Digital Output) |
| `mclGetGaplessMode` / `mclSetGaplessMode(v)` | `0x5d44b4` / `0x5d28ac` | byte `0xa0ab89` (`MCL_GAPLESS`); set stores it first; for `v == 0` with the preload word `0xa0abd0` == 1 it sends `{mcl-closegapless\null}` to the hciplayer socket (`0xa0abec`, when not -1) and stores -1 in the preload word |
| `mclGetReplayGain` / `mclSetReplayGain(v)` | `0x5d44e4` / `0x5d292c` | word `0xa0abb8`; set: only `v < 3`: store, then `send("{mcl-replaygain\%d}")` to the socket when it is not -1 |
| `mclGetDsdMode` / `mclSetDsdMode(v)` | `0x5d44fc` / `0x5d29d8` | word `0xa0abb4`; set: only `v < 3`: store, then `send("{mcl-dsdmode\%d}")` |
| `mclGetJumpFolder` / `mclSetJumpFolder(v)` | `0x5d4450` / `0x5d4468` | byte `0xa0ab88` (store only) |
| `mclGetOutputWay` | `0x5d45a4` | word `0xa0abe8`: 0 built-in, 1 Bluetooth, 2 USB audio (`set_outputchannel` `0x4d6f68` calls `mclSetOutputWay` with 0 for selectors 0 and 1, 1 for selector 2, 2 for selector 3) |
| `mclGetPlayMode` / `mclSetPlayMode` | `0x5d3628` / `0x5d278c` | hooked, [shuffle](shuffle.md) |

`config_mplayer` (`0x4d869c`, run when the player (re)starts) re-applies the play speed, the EQ, `mclSetGaplessMode(mclGetGaplessMode())`, `mclSetReplayGain(mclGetReplayGain())`, `mclSetPlayMode(mclGetPlayMode())` (the displayed mode, [shuffle](shuffle.md)) and `mclSetDsdMode(mclGetDsdMode())`. It does not re-apply the filter, the gain, the DAC count or the digital output: those reach the driver at config_init and from the click handlers only.

### Volume: `set_devicevolume`, the Line Out and the output selector

`volume` is the word `0x97cb10` (`G_VOLUME`, `[PLAYSET] VOLUME`, written by the volume keys, the volume dialog and SyncLink). `max_volume` is `0x97cb08`, `boot_volume` `0x97cb04`, `boot_volflag` byte `0xa05ac8`, `balance` `0x97cafc`, `btvolume` `0x97cb0c` (`[PLAYSET] BTVOLUME`), `headset_output` `0xa05a10` (the output selector of `set_outputchannel`: 0 3.5 mm, 1 balanced, 2 Bluetooth, 3 USB; the value 2 is tested by the Max Volume and Balance handlers below), `usbvol_mode` word `0xa05aac`.

`set_devicevolume(v)` (`0x4d6cf8`) is how every volume change reaches the hardware. Read in full:

1. Line Out byte `0xa05aa7` set and `mclGetOutputWay() == 0`: `mclSetVol(100, 100)` (`0x4d6d40`) and a tail call of `notifyVolume` (`0x50ef5c`); the level, the balance and the Max Volume are ignored.
2. else if `mclGetOutputWay() == 2` (USB audio): `mclUsbAudioSetVol(a, a, "hw:1")` with `a = 100` when `usbvol_mode == 0` (Volume Fixed) and `a = v` otherwise (Volume Variable) (`0x4d6d84..0x4d6de4`), then `notifyVolume` and a tail call of `0x4f1050`.
3. else (built-in, Bluetooth): the Balance: `balance` (0..20, centre 10, `0x97cafc`): for `balance < 10` the right level is `v + balance - 10`, the left `v`; for `balance > 10` the left is `v - (balance - 10)`, the right `v`; both clamped to 0..100 (`0x4d6e44..0x4d6e88`); then `mclSetVol(left, right)` (`0x5d4cb0`: `ioctl(fd, 0xc0044d00, (left << 8 | right) & 0xffff...)`, and the hciplayer text `{mcl-setvol\N}` when the output way is 1). An AirPlay stream scales the two levels with a float factor (`0x4d6ea0..0x4d6ee4`, not traced).

The Line Out byte also: shown by the status bar ([lineout](lineout.md)); makes the volume keys inert (`on_wm_keyup_fun` `0x4cdbe4..0x4cdbec`: key `0xdc/0xdd` with the byte set branches to `0x4cdc54` instead of opening `dialog/volume_dialog`; the other uses at `0x4cda70`, `0x4cdb58`, `0x4cdbb8` are not traced); is replied to SyncLink (`responseGetVolume`, `0x50eeb4`: max volume, volume, Line Out); disables the Gain row, the Gain tile and the `audiosetting_page` Gain row; and at boot forces the gain (below).

### Boot: what config_init does with these words

`config_init` (`0x4e5030`) loads each key with `toolsReadConfig(..., "/mnt/data/config.ini", default)` and `atoi`, in the order the sections below give. The shipped `assets/default/raw/config.ini` has `[PLAYSET] VOLUME=20, BTVOLUME=50, MEMORYPLAY=2, GAPLESS=0, REPLAYGAIN=0, FILTER=3, GAIN=0, BALANCE=10, PLAYMODE=3, JUMPFOLDER=1` and `[SYSSET] DSDMODE=0, USBVOLMODE=1, OUTPUTWAY=0`; the keys not in it (`MAXVOLUME`, `BOOTVOLFLAG`, `BOOTVOLUME`, `DACNUM`, `DIGITALMODE`, `FOLDERCOVER`) read their code default.

Its tail (`0x4e6a64..0x4e6ae4`): if the Line Out byte is set, `mclSetGainMode(1, 0)` (high gain, hardware only, the word untouched); if `boot_volflag == 0`, `volume = boot_volume`; if `max_volume < volume`, `volume = max_volume`; `set_devicevolume(volume)`; if the Line Out byte is set, `mclSetGainMode(1, 0)` again.

## Per row

Conventions: "the state" is stock's word or byte; "config" is the `write_int_config(value, section, key)` (`0x4d6a2c`) the handler makes; "load" is what `config_init` does with the key. A pair of addresses in one line is read as written in order. `sb`/`sw` in a call's delay slot executes before the callee.

### Play Mode (id 3)

- **State**: the mcl word `0xa0abe0` plus our Shuffle flag ([shuffle](shuffle.md)); shown through `sh_display_mode` (`pod_play_mode()`): 0 List Play, 1 Repeat Track, 2 Shuffle (the request, never stock's own mode 2), 3 Repeat All. Config `[PLAYSET] PLAYMODE`; load `0x4e5948..0x4e596c`: value >= 4 becomes 0, `mclSetPlayMode(v)`, shipped 3.
- **Page** `playset/playmode_page` (init `0x49fe38` walks `0x49f8d0`, then marks the shown mode): four rows `listitem1..4` = List Play (`playmode_listplay`), Repeat Track (`playmode_repeattrack`), Shuffle (`playmode_shuffle`), Repeat All (`playmode_repeatall`), whose handlers `0x49fde4`, `0x49fd90`, `0x49fd3c`, `0x49fce8` call the set function `0x49fb58(window, 0..3)` when `mclGetPlayMode()` (the shown mode: hooked at `0x49fd04`, `0x49fd58`, `0x49fdac`, `0x49fe04` and in the set function `0x49fb90`) is not already that index.
- **Set function `0x49fb58(win, i)`** in order: the images (`image_choice<i+1>` selected, the old one unselected), `mclSetPlayMode(i)` (`0x49fc7c`, hooked), `notifyPlayMode()` (`0x49fc8c`), `dmrSendPlayMode(i)` (`0x49fc9c`), `write_int_config(i, "PLAYSET", "PLAYMODE")` (`0x49fcbc`). Applied at once; no confirmation.
- **What our picker calls.** Not stock's set function (it needs stock's widgets) and not a bare `mclSetPlayMode`: `pod_set_mode(m)` (`patch/shuffle.c`, `home.h`), with `m` in 0..3 as above, and the current value from `pod_play_mode()`. `pod_set_mode` is `set_mode(m, 0)`: `mclSetPlayMode(m)` through the hook (2 turns the flag on over stock List Play and reorders the current queue, any other value turns it off and restores the order, `0x5d278c`), then `notifyPlayMode()`, `dmrSendPlayMode(sh_display_mode())`, `write_int_config(m, "PLAYSET", "PLAYMODE")`, nothing when `m` is already the shown mode. That is stock's sequence (`0x49fc7c..0x49fcbc`) with the hook's meaning of 2. `pod_set_shuffle(on)` is the Queue page's separate Shuffle switch (the repeat mode kept) and is not what this row uses. Not verified: that a Shuffle request with the flag already on and a Repeat mode set (`set_mode_now`'s first branch, `sh.keep`) is wanted from this row.

### Gain (id 0)

- **State**: word `0xa0abbc` (`mclGetGainMode`): 1 High (`gain_high`, image `pset_high`), 0 Low (`gain_low`, `pset_low`) (builder `0x4a0904..0x4a0968`: `== 1` shows high). Config `[PLAYSET] GAIN`; load `0x4e57a0..0x4e57c8`: value >= 2 becomes 0, `mclSetGainMode(v, 1)` (the second argument is set at `0x4e57b4`, in the delay slot of the `atoi` call, so it relies on `atoi` keeping `a1`: not verified); shipped 0.
- **Click `0x4a021c`**, in order: return when the Line Out byte `0xa05aa7` is set (`0x4a0224`); `old = mclGetGainMode()`, `new = (old == 0)` (`0x4a0230..0x4a023c`); `write_int_config(new, "PLAYSET", "GAIN")` (`0x4a0258`); `mclSetGainMode(new, 1)` (`0x4a026c`: stores the word and `ioctl 0xc0044d0d`, live); the row image. No confirmation, no volume change, no toast; Gain does not touch the volume (the output level change is the driver's).
- **Disabled** only while Line Out is set (above). Bluetooth and USB do not disable it. At boot with Line Out set the gain is forced high without changing the word or the saved `GAIN` (`mclSetGainMode(1, 0)`, tail of config_init).
- **Other writers** (all repeat the same two calls, config first): the pull-down Gain tile (`0x474754`: reads `mclGetGainMode`, `write_int_config(new, "PLAYSET", "GAIN")` at `0x474828`, `mclSetGainMode(new, 1)` at `0x47483c`; it returns without doing anything when the Line Out byte is set, `0x4747bc..0x4747c4`), the `audiosetting_page` Gain row (`0x528ba0..0x528be8`), config_init. The Output tile's Line Out toggle (`0x474890`, below) calls `mclSetGainMode(1, 0)` going to Line Out (a confirmation `msg_lowarn`, "Line Out sets max volume,continue?", first: `navigator_to_with_context("dialog/confirminfo_dialog")` at `0x474940`, result `0xa` = yes) and `mclSetGainMode(mclGetGainMode(), 0)` (`0x474ac0`) going back, so the stored gain is what returns. The SyncLink protobuf has `GetGainResp` / `SetGainReq` classes, but no handler calls `mclSetGainMode` (callers: the list above only).
- **Loudness.** The two states are two driver gain settings (ioctl value 0 or 1); what level the high setting adds is hardware and not read. The click makes no volume call (no clamp, no `set_devicevolume`, no confirmation), so any level change with the gain happens in the driver at the same volume number. Our row must call `mclSetGainMode(new, 1)`, never `store = 0` (that would leave the word, and every reader of it, unchanged).

### Digital Filter (id 1)

- **Page** `playset/filter_page` (init `0x49ed6c`; the list walk is `0x49e540..0x49e95c` in the Equalizer's range): eight rows `listitem1..8` (index `0..7`), handlers `0x49ed18` (0), `0x49ecc4` (1), `0x49ec70` (2), `0x49ec1c` (3), `0x49ebc8` (4), `0x49eb74` (5), `0x49eb20` (6), `0x49eacc` (7), each calls `0x49e95c(window, i)` when `mclGetfilter() != i`. ### DSD Output Mode (id 6)

- **State**: word `0xa0abb4` (`mclGetDsdMode`): 0 `dsdmode_d2p` "D2P", 1 `dsdmode_dop` "DOP", 2 `dsdmode_native` "Native". Config `[SYSSET] DSDMODE`; load `0x4e5de0..0x4e5dfc`: no clamp in config_init (the atoi result goes to `mclSetDsdMode`, which ignores values >= 3); shipped 0.
- **Page** `systemset/dsdmode_page` (init `0x4a64b4`, in the Display range of the symbol table): `listitem1..3` = D2P, DOP, Native, handlers `0x4a6460` (0), `0x4a640c` (1), `0x4a63b8` (2), each calling the set function `0x4a61f8(window, i)` when `mclGetDsdMode()` differs.
- **Set `0x4a61f8`**, in order: the images, `write_int_config(i, "SYSSET", "DSDMODE")` (`0x4a632c`), `mclGetOutputWay()` (`0x4a633c`); if it is 2 (USB audio): `save_stop_player()` (`0x4a6354`: `mclGetPlayStatus`; unless it is 1, saves the position, mutes, `usleep`, `mclStop`, notifies); `mclSetDsdMode(i)` (`0x4a6364`: stores and tells the hciplayer); `mclGetOutputWay()` again (`0x4a6374`); if it is 2: `save_start_player(0)` (`0x4a638c`: restarts at the saved position, notifies, `usleep`).
- **Conditions**: the page applies to every output but the stop and restart of playback happens only on USB audio; the page itself is not disabled by output. Whether the hciplayer uses the mode on the built-in DAC is not read.

### Digital Output (id 12)

- **State**: byte `digital_flag` `0xa05ac1`. Config `[PLAYSET] DIGITALMODE`; load `0x4e586c..0x4e58a0`: value >= 2 becomes 0, `andi 1`, `mclSetLineOut(v)` then the byte stored (delay slot); default string `"0"`.
- **Click `0x4a0418`**, in order: `byte ^= 1` (stored in the delay slot of the save, `0x4a0444`), `write_int_config(byte, "PLAYSET", "DIGITALMODE")` (`0x4a0440`), `mclSetLineOut(byte)` (`0x4a0450`), the switch image.
- **What it controls** (read, not inferred): an `ioctl(fd, 0xc0044d06, &byte)` on the audio driver (`mclSetLineOut`, `0x5d5ec8..0x5d5ed8`; the word is not kept by mcl), and the byte itself, whose only other readers are the status bar's `show_sysbar_face` (`0x544fcc..0x544fe4`: a bar widget visible when the byte is non-zero, hidden otherwise) and the pull-down's `dropdown_showface` (`0x475b14`, same). The status-bar widget is the digital-out glyph ([lineout](lineout.md)). What the ioctl does in the hardware (a digital audio output on the connector) is not verified. It has no relation to the Line Out byte `0xa05aa7`, to `DACNUM` or to the output selector.

### USB Audio Output (id 7)

- **State**: word `usbvol_mode` `0xa05aac`: 0 `usbvol_fixed` "Volume Fixed", 1 `usbvol_adjust` "Volume Variable". Config `[SYSSET] USBVOLMODE`; load `0x4e5e3c..0x4e5e78`: value >= 2 becomes 1; shipped 1.
- **Page** `systemset/usbvolmode_page` (init `0x4afbb0`; shares the code range of `systemset/usbset_page`): two rows, handlers `0x4afb68` (0) and `0x4afb1c` (1), each calling `0x4af9a4(window, i)` when the word differs.
- **Set `0x4af9a4`**, in order: the images, `usbvol_mode = i` (`0x4afac8`), `set_devicevolume(volume)` (`0x4afacc`: re-sends the volume to the USB DAC: 100 when Fixed, `volume` when Variable, whatever the current output is; set_devicevolume decides), `write_int_config(i, "SYSSET", "USBVOLMODE")` (`0x4afaec`).
- **What it controls**: only the USB audio branch of `set_devicevolume` (branch 2): with a USB DAC as the output (way 2), Fixed sends level 100 to the DAC (`mclUsbAudioSetVol(100, 100, "hw:1")`) so the volume is set on the DAC itself; Variable sends `volume`. With any other output the word has no effect.
- **Loudness**: switching to Fixed with a USB DAC connected sets the DAC's level to 100 at once.

### Single Dual DAC (id 11, never listed)

Load `0x4e5808..0x4e582c`: value >= 2 becomes 0, `mclSetDacNumer(v)`. Only the builder omits the row; the case is unreachable from the list. Not part of our page.

### Folder Album Cover (id 15)

- **State**: byte `foldercover_flag` `0xa05a67` (`FOLDER_COVER` in `tools/pod.py`). Config `[PLAYSET] FOLDERCOVER`; load `0x4e5a14..0x4e5a50`: value >= 2 becomes 0, `andi 1`, default string `"1"` (on); not in the shipped `config.ini`.
- **Click `0x4a04a8`**: `byte ^= 1` (stored in the delay slot of the save, `0x4a04d4`), `write_int_config(byte, "PLAYSET", "FOLDERCOVER")` (`0x4a04d0`), the switch image. Nothing else.
- **Readers** (`callers 0xa05a67`): (1) the stock folder row, `is_folderplaying` `0x532b60` (`folders.md` pins this word: the flag selects the cover `/mnt/mmc/.downpic/fd_<md5>.jpg` in place of the folder icon); our Folders page reads the byte as well ([folders](folders.md) "Covers": Off keeps the plain rows, On shows a cover only where one exists); (2) the cover task `parse_albumcovertask_thd` `0x4dddc0`: its folder branch (the item type test at `0x4dddac`) is skipped when the byte is 0, and with 1 checks the card (`check_tfstatus` `0x4ce3b4`) and makes `/mnt/mmc/.downpic` (`mkdir -p`) before working (the rest not traced); (3) the code at `0x5322f4` and `0x53240c` (inside `cdripper_page_init`'s range in the symbol table), which with the byte set and a counter `0xa0554c > 0` frees image-manager memory when `toolsGetSysMemFree` is below `0x6400` (not traced further). It does not play any role in Now Playing's art.
- **Our switch** (Settings > Library, built): a row calling exactly the click's two stores (`byte ^= 1`, `write_int_config(byte, "PLAYSET", "FOLDERCOVER")`); the Folders page re-reads the byte when its window comes back, so the change shows without a rebuild.

### Max Volume (id 4)

- **State**: word `max_volume` `0x97cb08`, 0..100. Config `[PLAYSET] MAXVOLUME`; load `0x4e5424..0x4e5468`: default string `"100"`, value >= 101 becomes 100. 0 is allowed (volume keys can then raise nothing).
- **Page** `playset/maxvol_page` (init `0x49f368` walks `0x49edf0`, then refresh `0x49efec`): `label_vol` text `"VOL: %d"` and `vol_slider` value both from the word (`0x49f084..0x49f0cc`), the slider `0..100` (`value` property check `< 0x65`), `btn_dec` `0x49f16c`, `btn_add` `0x49f0f4`, the slider's handler `0x49f24c`. The page init's walk (`0x49edf0`) binds the slider on **EVT_VALUE_CHANGING (0x11d)** (`0x49ef68`, handler `0x49ef6c`) and no other event (not EVT_VALUE_CHANGED 0x11c: an earlier reading of this section said "value-changed", the disassembly disagrees), the two buttons on EVT_CLICK 0x10c (`0x49ee68`; handlers `0x49efb4`, `0x49efe0`), each with the window as context: stock saves on every changing event of a drag and nothing on release. The page shows no volume (only `label_vol` from `max_volume`), so a volume key press (the volume dialog opens over the page) changes nothing it shows, and the handlers read `volume` when they run.
- **Handlers**, in order:
  - add `0x49f0f4`: if `max < 100`: `max += 1` (`0x49f138`), `write_int_config(max, "PLAYSET", "MAXVOLUME")` (`0x49f13c`), refresh. Never touches the volume.
  - dec `0x49f16c`: if `max > 0`: `max -= 1` (`0x49f1ac`); if `max < volume` (`0x49f1b4`): `volume = max` (`0x49f1c4`), and when `headset_output != 2` `set_devicevolume(volume)` (`0x49f1d8`), then `write_int_config(volume, "PLAYSET", "VOLUME")` (`0x49f1f4`); then in every case `write_int_config(max, "PLAYSET", "MAXVOLUME")` (`0x49f210`), refresh.
  - slider `0x49f24c`: `v = value` (ignored above 100); `max = v` (stored in a delay slot at `0x49f2c0`, always); if `v < volume`: `volume = v` (`0x49f2c8`), `set_devicevolume` when `headset_output != 2` (`0x49f2dc`), `write_int_config(volume, "PLAYSET", "VOLUME")`; then `write_int_config(max, "PLAYSET", "MAXVOLUME")` (`0x49f314`), refresh, `reset_poweroptions_timer(1, 1, 1)` (`0x49f340`).
  Nothing is applied on exit: every change is live. The volume is lowered only when the new max is below it; a raised max never raises it. The Bluetooth volume (`btvolume`) is not clamped by these handlers (the `headset_output == 2` test skips the device call, and `volume` is still lowered and saved).
- **Readers**: the volume keys' up step (`on_volume_tsup_fun` `0x47dff0..0x47e010`: `volume < 100` and `volume < max_volume` before `volume += 1`, `set_devicevolume`, `write_int_config(volume, "PLAYSET", "VOLUME")`); the volume dialog's slider (`0x47e2c0..0x47e318`: a value above the max sets the slider back to the max and uses the max); config_init's tail (clamp `volume` to the max at boot); SyncLink `responseGetVolume` (`0x50eeb0`, `notifyVolume` `0x50efa8`: the max is reported to the app). Line Out ignores it (set_devicevolume branch 1).
- **Loudness (subtle).** (1) The clamp of `volume` is part of the handler's contract: a setter that stores the new max without lowering `volume` leaves a volume above the max until the next key press (the keys then step from it). (2) The order in the dec and slider handlers is `volume` stored, device call, `VOLUME` saved, then `MAXVOLUME` saved. (3) `set_devicevolume` is called only when `headset_output != 2`; with Bluetooth selected the `volume` word is lowered and saved but nothing is sent. (4) The max is not applied by `set_devicevolume` itself; only the key paths, the dialog and these handlers keep `volume <= max`.

### Default Volume (id 5)

- **State**: byte `boot_volflag` `0xa05ac8` ("Vol. Memory", `bootvol_memory`: 1 = the last volume is kept, 0 = `boot_volume` is used at boot) and word `boot_volume` `0x97cb04`, 0..100. Config `[PLAYSET] BOOTVOLFLAG` (load `0x4e548c..0x4e54c8`: value >= 2 becomes 0, `andi 1`, default string `"0"`) and `[PLAYSET] BOOTVOLUME` (load `0x4e54ec..0x4e5518`: default string `"30"`, value >= 101 becomes 30).
- **Page** `playset/bootvol_page` (init `0x49d544`; refresh `0x49d160(window, mode)`): a switch row `btn_memory` (`img_switchmemory`) and a `bootvol_view` holding `label_vol` ("VOL: %d"), `vol_slider` 0..100 (EVT_VALUE_CHANGING 0x11d only, `0x49d0dc`) and `btn_dec` / `btn_add` (EVT_CLICK 0x10c, `0x49cfd4`). The refresh with mode 2 shows the switch from the byte and, with the byte set, hides and disables `bootvol_view` (`0x49d2d8`, `0x49d2ec`; visible and enabled when 0); mode 1 writes the label and slider from the word.
- **Handlers**, in order: switch `0x49d328`: `byte ^= 1` (stored in the delay slot of the save, `0x49d36c`), `write_int_config(byte, "PLAYSET", "BOOTVOLFLAG")` (`0x49d368`), refresh mode 2. dec `0x49d39c`: if `> 0`: `word -= 1` (`0x49d3e0`), `write_int_config(word, "PLAYSET", "BOOTVOLUME")` (`0x49d3e4`), refresh mode 1. add `0x49d4c8`: if `< 100`: `word += 1`, same save. slider `0x49d418`: `v = value` (ignored above 100), `word = v` (`0x49d478`), save, refresh mode 1, `reset_poweroptions_timer(1, 1, 1)` (`0x49d4ac`).
- **Not applied now**: no handler changes `volume` or calls the device; the value is used at boot only (config_init tail above), where it is then clamped by the Max Volume.
- **Loudness**: Default Volume is a boot-time level. With Line Out set, set_devicevolume forces 100 whatever it is (branch 1). With the memory switch on, the page hides the slider but the word keeps its value (the switch off shows the old number again).

### Channel Balance (id 13)

- **State**: word `balance` `0x97cafc`, 0..20, centre 10 (shown "L10" ... "0" ... "R10": `L(10 - b)` below 10, `R(b - 10)` above, `0x49cc2c..0x49ccbc`). Config `[PLAYSET] BALANCE`; load `0x4e58dc..0x4e5904`: value >= 21 uses the default (the code keeps the register); shipped 10.
- **Page** `playset/balance_page` (init `0x49ceec`; label refresh `0x49cb8c`): `slider_balance` (`value` property, 0..20), `btn_dec` `0x49ce4c`, `btn_add` `0x49ccd8`, slider `0x49cd78`; the walk (`0x49c990`) binds the slider on EVT_VALUE_CHANGING 0x11d (`0x49cb08`) only and the buttons on EVT_CLICK 0x10c (`0x49ca08`), the window as context.
- **Handlers**, in order: add `0x49ccd8`: if `balance < 20`: `balance += 1`, `write_int_config(balance, "PLAYSET", "BALANCE")` (`0x49cd1c`), label refresh, then when `headset_output != 2`: `set_devicevolume(volume)` (`0x49cd5c`). dec `0x49ce4c`: if `> 0`: the same with `-1`. slider `0x49cd78`: `v = value` (ignored above 20), `balance = v` (`0x49cdd8`), save (`0x49cddc`), label refresh, `set_devicevolume(volume)` when `headset_output != 2`, then `reset_poweroptions_timer(1, 1, 1)` (`0x49ce30`).
- **Effect**: only through `set_devicevolume` (branch 3 above): a built-in or Bluetooth way offsets the left or right level in volume steps; Line Out (way 0) and USB ignore it (branches 1 and 2). The page shows no such note.
## Pull-down Output tile (Line Out), for reference

`0x474890` (Control Center tile `img_outputswitch`): with the Line Out byte 0: asks `msg_lowarn` ("Line Out sets max volume,continue?") through `dialog/confirminfo_dialog` (`0x474940`); on yes (`0xa`) and the byte still 0: `mclSetGainMode(1, 0)` (`0x4749a0`), byte = 1 (`0x4749ac`), `write_int_config(1, "SYSSET", "OUTPUTWAY")` (`0x4749c4`), then when `headset_output != 2`: `set_devicevolume(volume)` (`0x4749e8`). With the byte 1 (back to PO): `mclSetGainMode(mclGetGainMode(), 0)` (`0x474ac4`), byte = 0 (`0x474ad4`), the same save and `set_devicevolume`. Our Gain row must re-read the Line Out byte on open and on `EVT_WINDOW_TO_FG` (the pull-down tile changes it from the pull-down, not from a stock page; whether the pull-down can be opened over our page, as it can over stock's, is for the page phase to check).

## Open questions

- **`headset_output == 2` is Bluetooth** by `set_outputchannel`'s selector mapping (selector 2 calls `mclSetOutputWay(1)`); the Max Volume and Balance handlers skip `set_devicevolume` for it. Not confirmed on a device; what stock does with a Bluetooth volume above the max is not read (the Bluetooth branch of the volume keys, `0x47e06c..`, is not clamped by `max_volume`).
- **Gain at boot**: `mclSetGainMode(v, 1)` relies on `a1` surviving `atoi` (`0x4e57b4`). If it is 0 the word is never loaded from `GAIN`.
- **`fd <= 0`**: the gain, filter, DAC and digital setters do nothing when the mcl driver fd (`0xa0abf8`) is not open; the config save still happens. When that can be true while our page is open is unknown. A test that runs stock's handlers needs the fd word set.
- **What High gain and the Digital Output ioctl do** in hardware: unknown (ioctl codes `0xc0044d0d`, `0xc0044d06` only).
- **ReplayGain / DSD mode in the hciplayer**: the text commands are sent; whether the mode applies on the built-in DAC and when is not read.
- **Folder Skip** and **Memory Playback Track vs Location**: the readers (`change_music`, `memeory_startplayer`) are not traced past where they read the byte or word.
- **SyncLink `responseSetVolume`** (`0x50eecc`): stores `[req + 0x10]` into `volume` only when `[req + 0xc] >= [req + 0x10]`, then `set_devicevolume` and saves `VOLUME`; the meaning of the two fields is not verified (a max-volume test is likely, not read). It does not clamp to `max_volume` itself.
- **Slider events**: stock's handlers are bound to the slider's EVT_VALUE_CHANGING only; whether AWTK emits it for every step of a drag or only at its pace is not read. `slider_set_value` (`0x6316dc`; stock's refresh, called with the handlers already bound when the page returns to the front) dispatches EVT_VALUE_WILL_CHANGE (0x11b, `0x63174c`) and, through `slider_set_value_internal`, EVT_VALUE_CHANGED (0x11c, `0x6317d8`), never EVT_VALUE_CHANGING (0x11d), so a refresh does not run the handlers. Display's brightness has the same shape.
- **`audiosetting_page`** keeps three stock sub-pages alive (above). The three open options: keep their assets, retire the page's rows, or give the three rows our own targets. Which stock path opens `audiosetting_page` from USB / Bluetooth is not traced.
- **Line Out while the page is open**: the Gain row's insensitive state follows the byte; a Line Out change by the pull-down cannot happen under the page, but SyncLink or a USB event changing `output_way` has not been checked (the byte's writers: config_init `0x4e5ec4`, the Output tile `0x4749ac`, `0x474ad4`; no other store was found by `callers`).
